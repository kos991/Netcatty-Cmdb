# nettopo CMDB 分类管理（阶段 D）· 验收记录

- 验收日期：2026-09-14
- 触发原因：用户反馈「**组织架构和分类不能自定义**」。
- 问题确认：阶段 A 只建了 `cmdb_orgs` / `cmdb_groups` / `cmdb_device_categories` 三张表并做**只读**列举——组织由旧台账同步时灌入科室，**分组与类型从无写入入口**，页面上只能看不能加。
- 本轮目标：把「组织 / 分组 / 类型」三维度做成**可自定义维护**（对应原计划阶段 D、nettopo 的「分类管理」）。

---

## 1. 证据依据

来自 `docs/evidence/nettopo/cmdb-resources.json`（实测）：

- 左侧三维度：`组织` / `分组` / `类型` 三个标签页
- 侧栏标题：`组织架构`，首项固定 `全部组织`，带 `+` 新增
- 工具栏按钮顺序（第一个即）：**分类管理**、批量编辑、批量克隆、批量删除、下载模板、批量导入、资产导出、新增资产

> 说明：实测账号仅「组织」维度可用，另两个维度为 VIP 限制，因此分组/类型的侧栏标题（`分组架构` / `类型架构`）为保持一致性推导命名，未逐字实测。

## 3. 关键实现

1. **一套代码管三个维度**：`cmdbTaxonomyTables` 白名单把 `orgs/groups/categories` 映射到具体表与被资产引用的外键列（`org_id`/`group_id`/`category_id`），**外部输入不拼接进 SQL**，未知维度直接报错。
2. **层级支持**：`parent_id` 组树，`parent_id=0` 为顶级；列表同时返回 `child_count` 与 `asset_count`，便于判断能否删除。
3. **三层删除保护**（避免把资产归属变成悬空引用）：
   - 有子节点 → 拒绝，并说明还有几个子节点
   - 已被资产引用 → 拒绝，并说明被几台资产引用
   - 不存在 → 明确报错
4. **防成环**：更新时禁止把节点挂到自己或自己的子孙下（先求后代集合再校验）。
5. **同级唯一**：依赖既有唯一索引，重复时报「同级下已存在同名X」。
6. **UI 双入口**：侧栏树上「+」直接新增下级并预置上级；也可从工具栏「分类管理」进入做全维度维护。

> **未做实**：实测工具栏还有「批量编辑/批量克隆/批量删除/下载模板/批量导入/资产导出/新增资产」7 个按钮，它们依赖资产写接口（原计划阶段 B/E），本轮**没有做成假按钮**。

## 6. 已知限制

1. **分组与类型当前仍为空**：本轮只提供了维护能力，**没有替用户预造业务数据**（不擅自往真实库塞分类）。需要用户点「分类管理」自行新增。
2. **资产尚未赋予分类**：`cmdb_assets` 的 `category_id/group_id` 依赖编辑资产功能（原计划阶段 B）才能赋值，因此仪表盘「设备分类分布」目前仍显示「未分类」。
3. **工具栏其余 7 个按钮未实现**（批量编辑/克隆/删除/下载模板/批量导入/资产导出/新增资产）：依赖资产写接口，属阶段 B/E，刻意不做假按钮。
4. **分组/类型的侧栏标题**（分组架构 / 类型架构）为推导命名，实测账号对这两维度为 VIP 限制，未能逐字核对。
5. **测试脚本自身踩坑两次**（PowerShell 变量名大小写不敏感、命令参数模式中 `+` 非运算符），已定位为脚本问题并修正后重测，**非应用缺陷**。

## 7. 结论

「组织 / 分组 / 类型」三维度**已可自定义维护**：支持层级新增、重命名、调整上级与排序、删除，并带三层删除保护与防成环校验；侧栏由只读列表升级为可操作的层级树，工具栏接入实测中排在第一位的「分类管理」入口。

**后端 21 个测试全绿，前端构建成功，10 项端到端核对全部通过。** 但仍缺浏览器级可视化验收（见第 5 节），exe 已重新打包，可直接双击预览。
