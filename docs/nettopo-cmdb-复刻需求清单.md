## 2. CMDB 核心层逐项需求（实测字段级）

### 2.1 资源列表页 `/cmdb/resources`

**左侧三维度**：`组织` / `分组` / `类型`（三个标签页，当前账号仅“组织”可用，另两个为 VIP 限制）。组织架构树首项固定 `全部组织`，带 `+` 新增。

**检索**：视图下拉（默认 `我的资产`）、搜索框占位符 `搜索资产 (名称, SN, IP...)`、`搜索` 按钮。

**工具栏 8 个按钮（实测顺序与文案）**：分类管理、批量编辑、批量克隆、批量删除、下载模板、批量导入、资产导出、新增资产。

**表格实测 30 列**（顺序严格一致）：
资产编号、设备名称、状态、设备分类、操作系统类型、操作系统版本、管理IP、业务监控、所属组织、所属分组、所属部门、负责人、序列号、MAC地址、厂商、型号、所属区域、楼层、机柜名称、位置标识、高度、起始U位、端口数量、电源类型、冗余电源、安装日期、保修到期、额定功耗、重量、操作。

- 资产编号列可排序，多列列头带筛选图标；行内操作为 `编辑` `删除` `⋯`。
- 状态以 Tag 渲染（在线/在库/报废/维护中/离线/故障），业务监控列显示 `未配置`。

**分页实测**：`共 11 条记录  当前 1-10  每页 10 条`（可选 10/50/100/300）、`上一页`、`第 1 / 2 页`、`下一页`、`跳至 __ 页`、`跳转`。

### 2.2 新增/编辑资产表单（实测 8 分区 54 字段）

| 分区 | 字段 |
| --- | --- |
| 基础信息 | 资产归属（当前登录用户/我的资产）、资产大类（物理硬件 Hardware）、资产编号（系统自动生成）、名称*、设备分类*、SN、资产标签(Tags，键值对)、状态（在库）、设备模型(模板)*、厂商、型号 |
| 凭证关联 | 添加关联凭证、新增凭证、尚未关联任何凭证 |

| 地理位置 | 省份、城市、区/县、经度(WGS84)、纬度(WGS84)、详细地址 |
| 网络配置（多网卡） | 主接口、接口名称、IP地址*、网络分区（管理网/业务网/外部子系统/内部网络/带外 OOB/未分类）、掩码/前缀、网关、MAC地址、接口凭证、备注；设备级 MAC 地址 |

| 其他信息 | 备注 |

### 2.3 资产详情面板（实测 10 页签）

左侧竖排分组导航：

- **资产**：信息、资产拓扑、设备机柜
- **监控**：业务监控、SNMP日志、核心指标
- **运维**：工单、LLDP、控制台审计
- **其他**：历史记录

**信息页实测字段**：

| 区块 | 字段 |
| --- | --- |
| 区域分类 | 所属数据中心、楼层、机柜名称、机柜位置、起始U位、高度(U) |
| IP 信息 | 管理 IP；无网卡时显示“该资产暂无网络接口” |
| Agent 实时运行状态 | 可折叠区块 |
| 基础信息 | 资产编号、名称、状态、设备分类、SN、厂商、型号 |
| 组织归属 | 所属组织、所属分组、部门、负责人、标签 |
| 电力与规格 | 额定功耗(W)、电源类型、冗余电源、重量(kg) |
| 采购与维保 | 安装日期、保修日期 |
| 端口与链路 | 端口列表 / ODF端口 / 物理链路（三个子页签）+ `新增端口` |

**其余 9 个页签实测内容**：

- 资产拓扑：拓扑中定位该资产节点（无节点时提示“拓扑中未找到该资产节点”）。
- 设备机柜：真实 42U 机柜图，展示 `42U | 600×800mm`、机柜功耗/额定功率/额定承重/散热输出，U 位逐格编号，已用/空闲/使用率统计，支持前面板、网格、放大、缩小、重置。
- 业务监控：总健康率、设备健康、异常设备、待完善、暂停探测、设备总数统计。
- SNMP日志：5s 自动刷新，近 15 分钟/30 分钟/1 小时/24 小时，复制、刷新；未关联 SNMP 凭证时明确提示。
- 核心指标：同款时间窗切换与自动刷新。
- 工单：该资产关联的工单记录。
- LLDP：`获取 LLDP 信息` 动作。
- 控制台审计：命令记录 / 操作录像两个页签，风险等级过滤（高/中/低/无风险），列 执行时间、用户、执行命令、风险等级。
- 历史记录：变更历史。

### 4.2 总体结论

| 复刻范围 | 工作量 | 单人周期 |
| --- | --- | --- |
| 只做 CMDB 核心层（P0） | 49-65 人天 | **2.5-3.5 个月** |
| P0 + P1 | 76-103 人天 | **4-5 个月** |
| P0 + P1 + P2 | 199-298 人天 | **10-15 个月** |
| 全站（P0~P3） | 294-468 人天 | **约 1.5-2 年** |

**关键判断：**

1. **P0 是唯一现在就能开工并验收的部分** —— 已拿到全部字段级证据，且不需要任何外部设备。
2. **P2 是真正的天花板**：SNMP、LLDP、控制台审计、备份、巡检、监控大屏都需要常驻采集端 + 真实网络设备。本项目当前是被动台账（SQLite + 人工录入），没有采集进程，也没有被管设备可联调。这部分即便写完也无法验证，属于“写了也不知道对不对”。
3. **P3 不建议做**：拓扑绘制引擎、Docker 应用商店、社区圈子是 nettopo 的产品护城河，不是中院资产管理系统的业务需求。
4. **与 AGENTS.md 的冲突必须先解决**：现有约束禁止新增关系表、人员表、复杂归档表，且明确要求保留“左侧导航 + 全局查询默认首页”的框架。复刻 CMDB 核心层必须新增 10 张表并重构导航，改之前需要用户书面确认。

## 6. 验收方式

- 后端改动：`go test ./...`。
- 前端改动：`web/` 下 `npm run build`。
- 页面手测：按本文档第 2 节字段逐个核对，对照 `docs/evidence/nettopo/` 截图。
- 未实际运行的验证一律不得标注为已通过。
