## Magpie 设计与实现规则（项目化适配）

来源：[Magpie Code Standards](https://github.com/yetone/magpie/blob/main/docs/code-standards.md)、[GUI app shell](https://github.com/yetone/magpie/blob/main/docs/subsystems/gui-shell.md)、[Subsystem design references](https://github.com/yetone/magpie/blob/main/docs/subsystems/README.md)。只吸收对本项目有用的行为规则，不移植 Magpie 的 Wails／网页实现或其完整导航。

### 交互与视觉

- 下拉和浮层按窗口可用空间定位；下方空间不足时翻到锚点上方；两边都不足时限制高度并让内容自身滚动。菜单不得裁在窗口外、遮挡后无法关闭或带动页面意外滚动。
- 菜单、悬停、按下、焦点、选中和禁用状态遵循同一套视觉规则。一个控件只表达当前状态，不叠加相互冲突的底色、边框、指示条；键盘焦点必须可见。
- 工具空间不足时先收紧工具显示，再缩短辅助路径，最后才截断标题；任何阶段都不能让工具压住标题、状态或彼此。图标化操作仍有可访问名称和悬停提示。
- 页面导航、详情打开、保存和关闭不产生意外滚动。确实需要定位对象时使用明确的主动滚动，并在改变筛选或布局后保持用户当前上下文。
- 动效只表达状态转移，支持系统减少动态设置；动效异常或视图尺寸变化不能让界面停在过渡中间态。不得用闪烁伪装业务进度。
- 用户明确调整的面板宽高、列布局和偏好不得被默认值覆盖。切页、刷新和异步响应不应丢草稿、选择或将较新结果覆盖成旧结果。
- 加载失败或数据无法读取意味着未知／失败，不等于零条、未占用、没有关联或成功。保留已有可用数据，显示可辨认错误；不得吞掉异常、伪造成功。

### 完整调用链与同类场景

- 交互修复从用户操作追到最终可见结果及持久状态：控件、页面状态、调用、响应、错误反馈、重新读取。按钮响应不证明目标页面或实际运行程序已更新。
- 修改筛选、分页、布局计算、超时或异步顺序时，找出使用相同规则的所有模块、资产类型、视口和回读路径，并验证相邻场景；不可只修演示截图中的一个对象。
- 跨平台、边界和竞态检查按本次改动风险选择；不能用一个平台成功推断其他平台。测试使用真实形状的输入，断言用户可观察行为，不绑定无关实现细节。
- 文档说明当前可观察行为、触发条件、状态转换、错误和兼容边界；提案写成提案，测试写出真实结果。文档、截图或测试本身不能替代实际运行验证。

### 与既有产品决定的冲突处理

- Magpie GUI 文档提到的侧栏／顶部导航切换、滚动行为和状态装饰不是本项目新增产品决定；必须服从本项目当前确认的 GPUI 顶栏、业务导航和操作方式。
- Magpie 的 GUI 规范禁止彩色左边框条，但本项目已确认资产网络类型细竖线及其动效；保留用户确认项，除非用户之后明确撤销。
- Magpie 使用 Wails/WebView，不据此替换 Rust + GPUI。该仓库规则作为实现质量参考，不作为整体架构或页面重设计指令。

以上为原则改写与链接，不复制分发完整第三方技能。技能缺少本机安装不阻碍执行AGENTS中的明确条款；不能谎称技能已自动安装、hook已拦截或所有未来会话一定遵守。

## 每轮内部验收清单

在已有任务记录中维护，不要求用户填表，也不为小改新增文件：

| 要求／禁止项 | 来源 | 影响面 | 验收方式 | 结果与证据 |
| --- | --- | --- | --- | --- |
| 按本轮实际要求填写，不填泛化套话 | 用户决定／参考图／既有规则 | 页面／状态／接口 | 可观察操作与期望 | 未实现／未验证／通过／失败；对应提交与日志或截图 |

规则：

1. 必须保留与明确禁止同样进入清单，用户新增要求叠加；已明确否定的旧要求标记撤销原因。
2. CI、启动、交互、视觉、业务闭环分别列状态。共享状态测试通过不能证明资产业务通过。
3. 用户提供截图时，在实际程序相同或接近尺寸下截图对照；逐项报告差距，不能只看整体是暗色就称符合Tern。
4. 子任务完成不关闭总目标；未验证不能写已完成，用户未授权缩减不得自行排除。
5. 技术障碍先查日志和官方契约；没有实际观测不能断言原因。遇真正权限／网络／平台阻塞时保留完整目标，说明已尝试及唯一缺失条件。
6. 修复误报要明确撤回哪一条，不用新的承诺覆盖。

## 当前基线，防止换会话后丢失

- Rust + GPUI 主线，参考 [Tern](https://docs.stencil.so/tern/) 桌面样式；GitHub Actions编译Windows，本机只运行下载产物验收。
- 四层职责：desktop、agent、cmdbd、engine。不得将尚未迁移的服务写成已实现。
- 顶栏只留Logo、标签、加号、窗口控制；去掉项目名、“资产全景”、额外全局搜索和通知、额外分栏文字按钮。标签与分栏功能保留。业务内容沿已确认原型，不恢复工作台，不擅自重画导航。
- 机柜保持有限可视范围，U位标尺独立，1U实际24px单行并有可见样例；具体布局沿原型，不用任意柜无限横向扩展。
- 旧代码删除有既有授权，不授权今后任意清空；保护文档与原型及用户新增修改。
- 当前可运行程序仅证明技术路径和部分交互；用户已否定其界面，视觉验收未通过。此前成功CI和窗口截图不得当作用户认可或完整桌面交付。
- 本轮仅更新执行规则和文档，不启动产品代码修改、编译、发布或技术栈切换。

## 最终报告格式

先写本轮是否满足约定目标。若未满足，首句列核心缺口。随后简述实际改动、可定位证据、未实现／未验证项。不要用“完成”概括“已推送”，不要让用户从最后一段才发现核心业务或界面没做。

文档规则本身不是自动验证器；它要求执行者出示可核查证据，但不保证模型永不犯错。本轮没有安装hook或修改全局工具配置。

## 网页原型设计与补齐契约

现有网页原型未完整定稿。其页面存在不代表设计完整、按钮可点不代表流程闭环、历史截图不代表用户认可。以下是补齐与核对要求，不是本轮已实现声明。

### 参考优先级与设计方法

1. 用户最新明确决定与标注截图优先；此前明确确认的业务设计继续保留；现有HTML仅提供已有实现参考。助手自行生成、被用户否定的草图或工作台不得成为基准。
2. Tern用于桌面顶栏、标签、面板层次与分栏风格参考；原型承担资产管理业务内容。不得照搬Tern代码编辑器、终端或媒体面板替代业务页面，也不能只套暗色就声称符合参考。
3. 先检查已有页面和交互，整理缺口，再在现有页面补齐。可以自主处理对齐、间距、溢出、焦点、错误状态等明确缺陷；改变导航、详情承载形式或删除操作须说明冲突并取得决定，不要求用户重述所有需求。
4. 风格统一到字号层级、行高、边距、图标、边框、圆角、主题色、悬停／选中／禁用／焦点。保持桌面业务密度，不加大面积无内容卡片、重复标题和解释条；重要状态与操作不能被长文本挤掉。
5. 草图请求给完整可审阅场景及关键细节，不用“这里是内容”代替主体。已有明确参考图时直接忠实表达，不借设计技能重新发明页面。

### 原型完整性与验收

- 按页面维护正常、空数据、加载、失败、长值、未配置、冲突、禁用、未保存切换等适用状态；只给有利的默认样例不算覆盖。不存在的真实接口错误可用明确标注的原型场景演示，不冒充后端结果。
- 菜单到表单到校验到结果反馈再到列表／详情回读形成可演示闭环。纯内存行为明确标注，不宣传落库、上传、采集或真实连接成功。尚无交互的设计标为缺口，不用空壳按钮充数。
- 在1568×718、1280×720和720px窄窗核对主要页面；截图实际检查遮挡、溢出、密度、弹窗边界、可滚动正文、分页和固定操作栏，并实点关键路径。不可只截图首页，或只检查DOM与console。
- 输出逐页差距表：已确认设计／现状／缺失／本轮修复／实际证据。尚未检查的项目标“待核对”，不能把本节列出的要求自动当成发现的缺陷或已完成结果。
- 网页原型先经过自身交互与视觉验收，GPUI迁移后再在原生窗口独立验收。原型截图不证明原生已实现；原生能运行也不证明原型已完善。
- 当前明确待办：现有原型完整性尚未逐页复核；Tern式桌面外壳与业务原型的完整衔接尚未通过用户确认。补齐工作由执行者依据已有要求主动推进，不转嫁成让用户逐个找错。本轮仅落盘设计约束，未宣称这些待办已完成。
