# IP 网段管理（子网定义）· 验收记录

- 验收日期：2026-09-14
- 触发原因：用户反馈「**你忘记了一个东西 IP 规划池，我不能定义专网外网内网，各各网段的名称**」
- 问题确认：IP 规划池里那 5 个网段（7/8/9/10段、外网）是**从 `ip_pool` 数据里反推出来的**，没有任何「网段定义」的地方——无法新增「内网」、无法改网段名、无法标明所属类别、无法填网关/VLAN/用途。
- 本轮目标：补上 nettopo IPAM 里的「**子网管理**」能力。

---

## 1. 根因与约束

| 项 | 说明 |
| --- | --- |
| 根因 | `ip_pool.subnet` 是自由文本，没有任何网段定义表；汇总接口用 `SELECT DISTINCT subnet` 反推，因此「没有 IP 的网段」根本不存在，网段名也不能改 |
| 硬约束 | `docs/nettopo-P0-实施计划.md` 明令**不得修改** `assets`/`asset_logs`/`ip_pool`/`servers`/`server_apps` 五张表的结构 |
| 应对 | 新增独立表 `ip_subnets` 承载定义；`ip_pool.subnet` 仍以**网段名称**关联，**重命名时级联更新** `ip_pool.subnet`，保证 IP 数据不断链 |

## 3. 关键实现

1. **网段定义字段**：名称、**类别（专网 / 外网 / 内网，可自定义）**、网段前缀、CIDR、网关、VLAN、用途、备注。
2. **自动补建**：启动时为 `ip_pool` 中已存在但未定义的网段补建定义记录（幂等）。类别自动推导（名称含「外网」→ 外网，其余 → 专网），前缀与 CIDR 从实际 IP 推导。
3. **不藏数据**：列表返回「已定义网段 ∪ IP 数据中出现过的网段」，后者标记 `未定义`，确保没有任何网段被隐藏。
4. **改名级联**：重命名网段时在同一事务内更新 `ip_pool.subnet`，IP 数据不会变成无主记录。
5. **删除保护**：网段下仍有 IP 时拒绝删除，并说明还有多少个 IP。
6. **空网段可见**：已定义但暂无 IP 的网段也会出现在总览卡片上（统计为 0），排在有网段的后面。
7. **顺序统一**：网段管理列表与总览卡片都按网段前缀自然排序（7 → 8 → 9 → 10 → 外网），修掉「10段」排到「7段」前面的问题。

## 6. 已知限制

1. **网段与 IP 仍以「名称」关联**：受「不得改 `ip_pool` 表结构」约束，无法加 `subnet_id` 外键。改名已做级联，但**若有人绕过界面直接改数据库里的 `ip_pool.subnet`，关联会断**。
2. **类别是自由文本**（预设 专网/外网/内网，可自定义）：不做枚举校验，避免限制用户；缺点是没有统一约束。
3. **排序字段未在界面暴露**：网段顺序统一按网段前缀自然排序，避免用户手动排序与总览顺序不一致；数据库仍保留 `sort_order` 作为同前缀时的次级排序。
4. **网段数量级**：网段管理是轻量列表（当前 5 个），未做分页。
5. **测试脚本核对文案时写错过一处**（把「该网段下若还有 IP」记成「同网段下若还有 IP」），已确认实际文案存在，**非功能缺陷**。
