## 2. 关键实现说明

| 模块 | 实现要点 |
| --- | --- |
| 仪表盘 | 8 区块全部由 SQL 聚合真实数据：总数、健康率（在线/总数）、需重点关注（离线+故障+维护中）、状态分布、最近新增、设备分类分布、部门分布、地理分布、异常设备、90 天内过保、最新工单。分布用 antd `Progress` 画条形，**未引入任何图表库**（避免新前端技术栈）。 |
| 编码与标签 | `cmdb_labels` 只存编码 + `asset_id` + 状态，资产名称/SN/部门/负责人/资产编号通过 `LEFT JOIN cmdb_assets` 带出，不重复存储。状态为**派生值**：`已归档` > `孤儿`（关联资产不存在）> `使用中`。批量生成用 `INSERT OR IGNORE ... SELECT` 保证幂等；修复孤儿先按编码回填关联、无法关联的转已归档。 |
| 工单管理 | 11 列严格对齐实测证据；类型/状态/结果三个下拉取值逐字来自证据；「所有类型/所有状态」等占位符**视为不过滤**（有测试覆盖）；导出在前端按当前筛选拉取全部匹配记录生成 UTF-8 BOM CSV。 |
| 资产盘点 | 8 列对齐；进度用 `Progress` 渲染；状态白名单 5 项来自证据。 |
| 凭证中心 | 7 列对齐；类型 7 项白名单来自证据；**只登记凭证元信息，不接收也不存储明文口令**（页内明示）。 |
| 配置中心 | 复用阶段 A 已建的 `cmdb_device_models`；支持分页、搜索、增删改、以及按「厂商,型号,高度,额定,最大,重量,深度」逐行批量导入（逐条校验并汇总失败原因）。 |

### 3.4 过程中发现并修复的真实缺陷

**工单号 / 任务编号重复**：原实现用秒级时间戳生成单号（`WO20260914191807`），**同一秒内创建的两条工单得到完全相同的工单号**（实测复现）。已改为「前缀 + 日期 + 自增 ID」（`WO202609140005`、`WO202609140006`），并新增回归测试 `TestCmdbAutoNumbersAreUnique` 锁定。

**仪表盘 SQL 列名冲突**：`SELECT ... AS name ... GROUP BY name` 与 `cmdb_assets.name` 冲突，报 `ambiguous column name: name`。已改用 `grp_name` 别名。该问题由 `TestCmdbDashboardDataKeys` 捕获。

## 5. 已知限制

1. **配置中心的「SNMP 采集配置」页签不含可编辑表单**：该项目依赖于常驻采集端与真实被管设备（原规划的 P2 阶段），本项目当前是被动台账，无采集进程、无设备可联调。该页签以明确说明替代空壳表单，不做假界面。
2. **业务 IP 仍无法用列表关键字检索**：业务 IP 存于 `cmdb_asset_interfaces`，资源列表关键字只覆盖 `cmdb_assets` 字段（阶段 A 遗留限制，本轮未变更）。
3. **`业务监控`、`位置标识` 两列恒为 `-`**：无对应数据来源，按实测 30 列保留。
4. **旧模块与 CMDB 仍是单向映射**：在旧台账模块新增/修改的数据不会自动出现在 CMDB，需再次触发同步。
5. **凭证不含口令存储**：出于安全考虑只登记元信息；若后续要做采集端联动，需要另行设计加密存储方案。
6. **工单「负责人 / 维护人员」筛选是文本输入**：实测环境中这两项是下拉，但本项目没有人员表（AGENTS.md 亦禁止新增人员表），故退化为文本匹配。
7. **仪表盘「设备分类分布」当前只有「未分类」**：阶段 A 未灌入设备分类数据，需等分类管理（原规划阶段 D）落地后才有真实分布。
