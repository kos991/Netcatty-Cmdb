# 凭证中心与管理／业务 IP 联动实施方案

> 本版按用户认可的功能范围修正此前的过度收缩：保留多凭证、多地址、业务与 IPAM 的真实联动，实施仍依托现有页面和调用链。本轮只修订计划，不实施业务代码。

**目标：** 将“关联”改为“凭证中心”，使共享身份真正用于连接；在服务器和安全设备中清楚管理多个管理/业务/接口地址，并与 IPAM、承载业务、Netcatty 快速连接对应。

**架构：** 沿用现有 Netcatty 主机、身份、钥匙串及 CMDB 资产、接口、应用和 IP 池。已有字段能表达的直接复用；确实缺少的数据只补在现有表中。现有云同步机制及项目隔离照常使用，新增字段需通过同一快照链路的往返测试。

**技术栈：** 现有 Go + SQLite、Netcatty 原生 React / Tailwind / Radix / Lucide。

## 一、需求边界与现状

- 必须保留：现有 Netcatty 主机/身份/钥匙串的直接创建、选择、单独关联、连接；三类资产原有的查询、分页、CRUD、照片、履历、归档和导出。
- 本轮补齐：多台设备复用同一身份；一台设备多个用途的连接/身份；管理、带外及多个业务/接口 IP；资产、IPAM、应用和指定 IP 的连接联动。
- 必须尊重：IPAM 网络/广播地址与预留规则、统计口径，普通终端和云桌面的现有 IP 字段分工、基础设施的上下联及 VLAN/VXLAN。
- 明确移除：用户可见的“关联”页签名称，以及“第一个接口必为管理 IP”的错误推导。
- 不新增独立凭证库，不重做五个模块，不改云同步架构，也不开展全网段扫描、主动 SNMP 采集或 Web 自动登录。当前方案无待确认的产品分支。

代码事实：`cmdb_asset_interfaces.ip` 目前一条接口记录只有一个 IP；`ip_pool` 只有一个占用对象；`server_apps` 有承载服务器和访问 URL，却没有“实际选用了哪个业务 IP”；`cmdb_netcatty_links.address` 已有目标地址摘要，但没有区分是否跟随资产地址。实施不能只修改显示文案。本次不向设备下发配置或修改设备密码。

## 二、问题一：关联改为凭证中心，支持现有身份复用

### 页面与行为

1. 基础设施的“关联”页签改为“凭证中心”，内部 relations 标识保留；终端和业务系统已有 Netcatty 区域沿用相同名称，不新增独立配置入口。
2. 现有主机、身份和钥匙串的关联、新建、解除、连接能力全部保留。新建项仍保存在 Netcatty，可被后续设备选择。
3. 多台设备可以选择同一个 Netcatty 身份，不复制账号密码；一台资产可以保留管理员、只读巡检、带外等多条连接，也可以单独关联备用身份。
4. 每条连接显示用途、协议、端口、真实目标地址、所选身份及默认标记。相同目标但不同身份时使用各自的原生主机配置，避免一条主机记录对应两个互相矛盾的账号。
5. 仅关联备用身份时只保存引用；选择“用于此连接”时，必须把身份实际应用到对应 Netcatty 主机。
6. 共享身份的编辑沿用 Netcatty 身份数据。修改保存值后，所有引用主机在**下次连接**时读取新值；单台设备使用不同密码时，在资产内创建独立身份并只切换这条连接。
7. 解除资产关联只解除引用，不删除原生主机或共享身份；身份失效时显示具体失效项，不回退到不明来源的旧密码。

### 必须修复的现有问题

当前 CMDB 保存 credential_id，而连接按 host_id 使用宿主主机原有身份。需要补齐“用于此连接”的宿主保存动作，避免选择了身份 B、实际仍使用身份 A。

修改主机认证时保留跳板机、端口转发、标签等其他配置。SSH/Telnet 使用各自已有认证字段；Telnet 不支持密钥时明确提示，不能伪造成功。已有原生主机只要被另一个资产引用，修改其认证前要显示影响范围；新增主机时直接绑定共享身份，旧资产的引用不受影响。主机和身份仍允许单独关联。

身份共享是复用 Netcatty 身份 ID；编辑保存密码不等于修改设备端密码，也不复制密码到 CMDB、Excel 或 IPAM。界面显示“身份引用有效”与“设备连接成功”两个不同状态。

## 三、问题二：管理 IP／业务 IP 与现有 IPAM 联动

### 页面与字段

- 服务器、安全设备在现有网络区域明确显示“管理 IP”和“业务 IP”，沿用 mgmt_ip/manage_ip 和 biz_ip 作为主要地址；其他地址在接口列表中展示。
- 服务器可同时登记系统管理、带外管理与多个业务地址；安全设备可登记管理口、内外网及 DMZ 接口，透明接口允许无 IP。
- 当前接口记录只容纳一个 IP。不同接口继续用现有列表；同一接口确有多个地址时，仅为该接口增加附加地址字段和读写处理，不能复制“物理接口”记录冒充另一张网卡。
- 管理 IP 用于默认快捷连接；网络页每个已关联的地址都有自己的连接入口。业务 IP 不自动成为管理 IP。
- 同一 IP 可以同时填作管理与业务用途，同设备只计一次占用。
- 网络页与凭证中心保持分开：网络展示地址、接口、IPAM 状态、业务引用和上下联；凭证中心展示主机、协议、地址及账号。保留 VLAN/VXLAN、照片和其他已确认内容。
- 普通终端和云桌面的现有 IP 规则不改；交换机、路由器的无地址接口不强制补 IP。

界面保持现有半屏工作区：设备顶部只突出“主要管理 IP＋连接”，网络区每行紧凑显示地址、用途、接口、IPAM 占用和对应操作；掩码、网关及完整业务引用展开看。新增地址默认只填 IP 与用途，接口和网段按实际情况选择。

### IPAM、业务系统与连接的关系

以服务器 A 为例：管理 IP `10.20.10.11`、带外 IP `10.20.10.12`、业务 IP `10.20.30.21`。系统甲和系统乙均使用 `10.20.30.21`，则 IPAM 只记一次“设备占用：服务器 A”，同时显示两项业务使用；服务器和两项系统都能打开彼此详情。系统自己的独立 VIP 才登记为“应用占用”。安全设备接口地址归安全设备，不因为转发业务就归应用。

已有 `server_apps.cmdb_asset_id` 记录承载服务器，本轮仅补一个明确的业务访问 IP 选择/保存位置，使应用能选承载服务器的某个业务 IP。多应用可以选同一设备 IP，IPAM 仍只有一个占用者。没有承载服务器的独立应用 IP 继续按现有 IPAM“应用占用”入口分配。应用访问 URL 保留手工值，不因为 IP 变化偷偷改写。

连接按“设备地址→关联的 Netcatty 主机→该主机实际身份”打开。不同 IP 可以分别有连接；同一 IP 可以配置管理员和只读两个原生主机。旧主机可能使用域名或 NAT 地址，显示实际目标并保留。资产内新建且选择跟随地址的连接，在该地址变更后更新其目标；只更新这个主机，不扫描或改写整个原生主机库。目标更新失败时展示旧目标与重试操作，不能显示该 IP 上的连接已经正确。

### 必须修复的现有断点

1. 编辑器不能仅因为业务接口排在第一位就把它作为管理 IP，也不能删除管理接口后自动改用其他业务接口连接。
2. 资产保存和 IPAM 分配使用一致的管理／业务字段与接口地址；IPAM 分配完成后，重新编辑资产不能被旧接口值覆盖。
3. 地址属于已建网段时使用现有 IPAM 条目；若池中尚无该地址，按现有网段规则登记并占用。未配置网段的地址在资产中保留并明确显示“未纳入 IPAM”，提供创建网段入口，不能伪装为已联动。
4. 同设备共用管理/业务 IP、同一接口多个地址时按真实 IP 去重。替换旧地址需检查管理字段、业务字段、所有接口及使用该地址的业务系统；仍有引用则保留占用或明确要求迁移/解除。
5. IPAM 反向分配管理 IP 时，资产顶部、编辑器和指定管理连接保持一致；分配业务 IP 时在网络区可见，业务系统可选择该地址。
6. 已关联主机的实际连接目标与所点 IP 不一致时显示二者。跟随模式按选定地址更新目标；独立域名或 NAT 地址维持原配置，不误连另一地址。
7. 快捷连接取最新 Netcatty 主机数据；未关联时带入**所点地址**创建原生主机并选择已有身份。
8. 业务系统展示实际选择的业务 IP；没有选择就显示未关联，不用管理 IP 顶替。

保留现有 IPAM 预留转分配、释放、分页、广播/网络地址识别和使用率。设备地址、应用独立地址、预留分别计数；多项应用使用同一设备地址不重复增加使用率。

当前代码建立 IPAM 条目要求先有网段，因此“资产填 IP”不能被描述为无条件自动创建 IPAM 占用；无网段时清楚提示并保留资产记录。释放地址时需要看到相关接口、业务和跟随连接，处理依赖后再释放；设备归档默认保留占用，不能暗中清空历史。

### 最小数据补充与兼容

| 已有表 | 仅补字段 | 实际缺口 |
| --- | --- | --- |
| `cmdb_asset_interfaces` | `additional_ips_json` | 同一接口目前只有一个 `ip`，需要在同一接口保存其余业务地址及用途；原 `ip` 和链路接口 ID 保持不变 |
| `server_apps` | `service_ip` | 应用选择承载服务器的哪一个业务 IP，或保存自身独立地址；空值兼容旧数据，不凭管理 IP 猜测 |
| `cmdb_netcatty_links` | `follow_asset_ip` | 区分资产中创建的跟随地址连接与已有域名/NAT 主机；旧记录默认不跟随，避免升级后批量改写原生主机 |

`additional_ips_json` 每项只记录地址与用途，如 `[{"ip":"10.20.30.22","purpose":"业务"}]`；同一接口原 `ip` 仍是兼容主地址，接口 ID、VLAN、上下联不改变。原有记录新增字段默认空，不凭数组顺序把某个地址推为管理地址。

这些是已有表的小字段，不建立新子系统。原管理/业务/公网 IP 字段、IPAM 的 `owner_type/owner_id` 和接口 `ip` 继续使用；旧记录不清空、不批量重写。一个 IP 同时用于管理和业务时，仍是一条设备占用，界面显示两个用途。

应用对设备地址的使用可按 `cmdb_asset_id + service_ip` 查询，独立应用 IP 使用现有 IPAM 的应用占用者字段；不把一个设备 IP 为两个业务重复分配。地址变更时展示受影响业务，用户在现有编辑流程中选择新地址；访问 URL 由用户确认，不静默替换。

最小字段必须同步补到当前接口、导入导出和现有云快照的字段往返验证中。先通过新旧数据快照测试；若现有读取层不保留新字段，只补当前序列化映射，不设计新的同步协议。不能因“不重做同步”就遗漏新增地址、业务或连接信息。
