# Netcatty Cmdb 统一资产工作区设计

## 1. 文档状态

- 状态：界面方向、业务边界及书面设计已由用户确认，进入实施计划编写阶段。
- 日期：2026-09-18。
- 适用范围：Netcatty 原生 Cmdb 的资产台账、动态档案、网络关系和数据交换。
- 后续范围：组织架构单独设计，不与本轮资产重构混合实施。

本设计覆盖此前“设备资产内部保留终端资产、基础设施、业务系统三个独立子页面”的决定。设备资产改为一张统一资产表，但不得删除各类资产已有的分页、筛选、详情、CRUD、导入导出、调换、维修、归档、履历及关联能力。

## 2. 背景与目标

现有设备资产按终端资产、基础设施和业务系统分为三个子页面，导致统一搜索、录入和详情展示反复切换；同时终端硬件配置不足，虚拟资源、软件许可、超融合、云桌面和网络链路缺少完整表达。

本轮目标：

1. 将全部资产放入同一张可搜索、筛选和分页的资产列表。
2. 顶层资产类别仅保留“设备资源、业务系统、软件许可”。
3. 使用具体资产类型和字段模板决定录入表单与详情档案字段，不让所有类型共用一个超长表单。
4. 统一“新增资产”入口，并保持首次建档简单。
5. 设备资源可与 IPAM、VLAN、VXLAN 及端口级上下联关系关联。
6. 完整管理超融合集群、超融合节点、云桌面平台、桌面池和云桌面终端之间的关系。
7. 延续 Netcatty 原生组件、暗色主题、紧凑密度和 Lucide 图标体系。

## 3. 非目标

- 不增加第四、第五个一级资产入口。
- 不实现链路聚合组、LACP、Eth-Trunk 或 Port-Channel 独立对象。
- 不要求首次新增资产时录入端口链路、完整 IPAM 或 VXLAN 信息。
- 不制作关系图编辑器或网络拓扑画布。
- 不引入 ORM、FTS、全局状态管理框架、Ant Design 或 MUI。
- 不在本轮重构组织架构和人员模块。

## 4. 统一信息架构

### 4.1 一级资产类别

| 一级类别 | 包含内容 |
| --- | --- |
| 设备资源 | 终端、服务器、网络设备、安全设备、存储、虚拟机、云资源、超融合、云桌面 |
| 业务系统 | 业务应用、基础支撑系统、数据库服务、监控系统等逻辑系统 |
| 软件许可 | 操作系统授权、数据库 License、SaaS 订阅、VMware、CAD、Office 等许可 |

“新增资产”只展示以上三个入口，避免菜单过长。进入“设备资源”后再选择具体设备类型。

### 4.2 设备资源字段模板

设备类型在配置中心绑定一个字段模板。模板决定新增、编辑和详情档案显示哪些字段；不适用字段不显示，也不要求填写。

| 字段模板 | 典型类型 | 主要字段 |
| --- | --- | --- |
| 电脑与服务器 | 台式机、笔记本、物理服务器 | 品牌、型号、SN、CPU、内存、硬盘、操作系统、IP、供应商 |
| 普通终端 | 打印机、普通终端 | 品牌、型号、SN、IP、位置、供应商 |
| 网络与安全 | 交换机、路由器、防火墙、安全设备 | 品牌、型号、SN、管理 IP、端口数量、位置、供应商 |
| 存储设备 | 存储阵列、备份设备 | 品牌、型号、SN、总容量、磁盘配置、RAID、管理 IP、供应商 |
| 虚拟机与云资源 | ECS、云主机、私有云 VM、容器、K8s Pod、云数据库实例 | 供应商、平台、实例标识、宿主机或集群、计算与存储规格、IP、运行环境 |
| 超融合集群 | HCI 集群 | 供应商、平台版本、管理地址、节点数量、容量汇总、高可用、运行环境 |
| 超融合节点 | HCI 物理节点 | 品牌、型号、SN、所属集群、CPU、内存、本地存储、管理 IP、供应商 |
| 云桌面平台 | VDI 管理平台 | 供应商、平台版本、管理地址、承载集群、授权数量、授权到期 |
| 桌面池 | VDI 桌面池 | 所属平台、桌面模板、容量、已分配数、vCPU、内存、系统盘、业务网段 |
| 云桌面终端 | 云桌面盒子、云桌面终端 | 终端主机 SN、显示器 SN、使用人、位置、物理 IP、虚拟桌面 IP、所属桌面池 |

网络与安全设备默认不显示 CPU、内存、硬盘、操作系统和 MAC。虚拟机、云资源和业务系统不显示物理品牌字段。

### 4.3 业务系统字段

- 系统编码、系统名称、系统类型、状态。
- 供应商、版本、运行环境、重要级别。
- 承载设备或虚拟资源、访问地址、端口。
- 中间件、数据库、负责人、所属部门。
- 上线日期和维护到期日期。

### 4.4 软件许可字段

- 许可编码、软件名称、许可类型、状态。
- 供应商、版本、授权数量、已用数量。
- 购买日期、生效日期、到期日期、负责人、部门。
- 适用设备、虚拟资源或业务系统的分配关系。
- 许可密钥仅保存必要元数据；默认脱敏展示，导出和云同步不得泄露明文秘密。

## 5. 统一资产列表界面

### 5.1 页头

```text
[搜索资产编码、名称、SN、IP、品牌、型号、供应商或许可证……]
                                      [新增资产 ▾] [刷新]
```

- 搜索框宽度约 `640-720px`，随可用空间收缩。
- 搜索覆盖所有一级类别和具体类型。
- 不显示“终端资产概览”或状态统计悬浮窗。
- 不显示终端资产、基础设施、业务系统三个页签。

### 5.2 筛选与操作

```text
[全部资产类别] [全部具体类型] [全部状态] [更多筛选]
                                      [模板] [导入] [导出]
```

- 一级类别只有设备资源、业务系统、软件许可。
- 具体类型根据一级类别动态过滤。
- “更多筛选”承载部门、负责人、供应商、运行环境、到期范围等低频条件。
- 导出使用全部当前匹配记录，不受当前页限制。

### 5.3 表格列

| 列 | 展示规则 |
| --- | --- |
| 资产名称 / 编码 | 主名称加资产编码 |
| 资产类别 / 类型 | 一级类别加具体类型 |
| 配置 / 供应商 | 按模板生成紧凑摘要，不要求所有类型使用同一字段 |
| 负责人 / 部门 | 当前责任人与组织归属 |
| 主要标识 | IP、SN、实例 ID、访问地址或到期日期中的主要标识 |
| 状态 | 使用对应类型的状态标签 |

硬件明细不拆成大量列表列。品牌、型号可进入配置摘要，CPU、内存、硬盘等完整内容放在详情档案中。

## 6. 统一新增与编辑

### 6.1 新增入口

```text
新增资产
├── 设备资源
├── 业务系统
└── 软件许可
```

选择一级类别后打开对应表单。设备资源先选择具体设备类型，再由绑定的字段模板生成表单。

### 6.2 表单分组

- 基础信息：编码、名称、具体类型、状态。
- 类型配置：根据字段模板显示硬件、平台、容量或授权字段。
- 归属与位置：人员、部门、位置、供应商。
- 网络与系统：只显示当前类型适用的 IP、操作系统或访问字段。
- 采购与维护：采购、质保、上线或到期日期。

首次建档只要求类型、名称及该类型最少必要字段。IPAM 分配、端口链路、VLAN、VXLAN 和复杂关联保存后在详情档案中按需补录。

## 7. 动态资产档案

右侧抽屉标题统一为“资产档案”。内容按具体类型动态组织：

1. 基础信息。
2. 类型专属配置。
3. 网络与链路，仅适用设备资源时显示。
4. 关联信息，例如承载、分配、平台、集群和桌面池关系。
5. 生命周期操作与运维履历。

空字段和不适用字段默认隐藏；历史数据中存在值但当前模板未显示时，编辑不得静默删除原值。

## 8. IPAM、VLAN、VXLAN 与端口链路

### 8.1 IPAM 联动

- 设备接口从 IPAM 选择地址。
- 选择 IP 后自动带出网段、网络区域和默认 VLAN。
- 地址分配和释放沿用 IPAM 占用规则，防止同项目重复占用。
- 档案中的 IP 可进入对应 IPAM 地址详情。
- 云桌面终端可同时关联物理 IP 和虚拟桌面 IP。

### 8.2 VLAN 与 VXLAN

- VLAN 作为可维护网络配置项，至少包含 VLAN ID、名称、用途和关联网段。
- VXLAN 至少包含 VNI、名称、用途和可选关联 VLAN。
- 设备接口可以关联一个 VLAN 和一个可选 VXLAN VNI。
- 桌面池和虚拟资源可以通过业务网段关联 VLAN/VXLAN，不重复手工录入相同信息。

### 8.3 端口级链路

链路必须精确到具体端口：

```text
服务器 eth0 → 接入交换机 Gi1/0/12
核心交换机 Gi1/0/24 → 边界防火墙 GE0/1
```

每条链路记录：

- 本端资产、本端端口。
- 对端资产、对端端口。
- 方向：上联或下联。
- 链路类型：Access、Trunk、管理或虚拟链路。
- VLAN、允许 VLAN、可选 VXLAN VNI。
- 速率、状态和备注。

一条物理连接只保存一条规范关系，由接口自动生成双方视角，避免双向重复录入。删除或修改链路必须同步影响两端展示并写入履历。

本轮不建链路聚合对象。用户可以按实际需要逐条登记物理端口，不影响资产首次建档。

## 9. 超融合与云桌面关系

关系链如下：

```text
超融合集群
├── 超融合节点
├── 承载虚拟机 / 云资源
└── 承载云桌面平台
    ├── 桌面池
    │   └── 虚拟桌面实例 / 分配记录
    └── 云桌面终端
```

### 9.1 超融合集群

- 汇总节点在线数、CPU、内存和存储总量及使用量。
- 节点资源为明细来源，允许保存外部平台采集的使用量快照。
- 集群档案可进入节点、承载平台及虚拟资源档案。

### 9.2 超融合节点

- 节点属于一个超融合集群。
- 节点保留物理硬件、管理 IP、IPAM、VLAN/VXLAN 和交换机端口链路。

### 9.3 云桌面平台和桌面池

- 云桌面平台可关联一个承载集群和多个桌面池。
- 平台记录授权总数、已分配数和授权到期日。
- 桌面池记录容量、已分配数、桌面规格、模板、业务网段和网络关系。

### 9.4 云桌面终端

- 终端关联使用人、桌面池和可选虚拟桌面实例。
- 终端物理 IP 与虚拟桌面 IP 分开管理，并分别联动 IPAM。
- 调换使用人、维修换件、注销归档及履历能力继续保留。

## 10. 数据模型策略

### 10.1 统一查询视图，不强制单表重写

统一列表是产品视图，不要求把现有 `assets`、`cmdb_assets` 和 `server_apps` 立即合并为一个巨型表。后端提供统一资产查询契约，将现有对象映射为统一摘要；新增的许可、网络配置和链路使用职责明确的新表。

统一摘要至少包含：

- `asset_kind`：`device`、`system`、`license`。
- `asset_type`：具体类型。
- `source_table`、`source_id`：现有对象定位。
- 名称、编码、状态、负责人、部门、主要标识和配置摘要。

详情、编辑和生命周期操作仍路由到所属领域存储，减少一次性迁移风险。

### 10.2 新增关系对象

- 设备类型到字段模板的绑定。
- 软件许可及许可分配关系。
- VLAN、VXLAN 网络配置。
- 资产端口和端口链路。
- 超融合集群成员关系。
- 云桌面平台、桌面池和终端绑定关系。

所有新表必须包含项目归属和稳定同步标识，沿用当前项目隔离、修订号和软删除规则。

## 11. API 与数据流

### 11.1 统一列表

- 新增统一资产列表接口，沿用现有 `list/total/page/page_size` JSON 风格。
- 支持关键词、一级类别、具体类型、状态、负责人、部门和供应商筛选。
- 统一搜索结果直接打开对应资产档案。

### 11.2 新增与编辑

- 前端先读取设备类型及字段模板定义。
- 提交时根据一级类别路由到对应领域接口。
- 后端验证字段模板必填项、项目归属、IP 冲突和关联对象存在性。
- 任一关联写入失败时事务回滚，不返回伪成功。

### 11.3 网络关系

- IP 分配复用现有 IPAM 接口和事务规则。
- VLAN、VXLAN、端口和链路提供独立 CRUD。
- 链路接口验证本端和对端不能相同、端口归属正确、同一端口不存在冲突占用。

## 12. 导入导出

- 统一导出按当前统一筛选导出全部匹配记录。
- 三个一级类别使用各自模板，避免一个 Excel 包含大量无意义空列。
- 设备资源模板按具体类型提供字段说明；不适用字段留空且不覆盖历史值。
- 超融合和云桌面关系支持单独关系表页签或专用关系导入。
- VLAN、VXLAN 和端口链路单独导入，避免首次资产导入过重。
- 导入先预览校验，确认后事务提交；失败不得保留半批数据。

## 13. 兼容与迁移

- 现有终端、基础设施和业务系统数据原地保留，通过映射进入统一列表。
- 原有终端调换、维修、归档、履历和导出接口继续可用，直到统一接口覆盖并通过回归。
- 迁移只新增表和列，不删除现有业务字段。
- 历史云桌面终端按现有设备类型映射到云桌面终端模板；不自动臆造桌面池或平台关系。
- 旧数据无法确认字段模板时归入“未分类设备”，由用户后续修正。

## 14. 错误处理与权限

- 字段模板加载失败时阻止新增并显示真实错误，不退化为空白表单。
- IP 冲突、端口冲突、无效 VLAN/VNI、失效关联必须明确提示具体对象。
- 删除被引用的集群、平台、桌面池或网络配置时阻止操作并列出引用数量。
- 软件许可密钥默认脱敏，导出、日志和前端错误中不得出现明文。
- 归档资产保留端口、IP、分配和履历关系，但默认列表隐藏。

## 15. 测试策略

### 15.1 后端

- 统一查询覆盖三类资产、筛选、分页和项目隔离。
- 动态字段模板验证及旧数据兼容。
- IP 分配、释放、VLAN/VXLAN 关联和冲突检测。
- 端口链路双方视角、重复端口阻断、归档保留。
- 超融合和云桌面关系完整性。
- 软件许可数量、分配和到期数据。
- 分类导入导出往返和事务回滚。

### 15.2 原生界面

- 一张列表展示三类资产，不出现旧的三个页签或概览悬浮窗。
- 搜索框在常用桌面宽度达到目标尺寸且不挤压操作区。
- 不同具体类型打开正确的新增表单和详情档案。
- 网络设备不显示无关硬件字段；虚拟资源不显示物理品牌。
- 端口链路在资产保存后补录，首次新增不被阻塞。
- 超融合、云桌面和软件许可关系可逐级进入详情。
- 深浅主题、加载、错误、空状态、分页和弹层无遮挡。

### 15.3 回归命令

- `go test -count=1 ./...`
- `node --test scripts/prepare-netcatty.test.mjs integrations/netcatty/cmdb/*.test.js`
- 装配后的 Netcatty 相关 lint、测试和完整构建。
- Electron 原生预览下进行关键流程截图和交互验收。

## 16. 分阶段交付

1. 统一查询契约和统一资产列表。
2. 统一新增入口、字段模板和动态档案。
3. 终端硬件字段、业务系统供应商及软件许可。
4. IPAM、VLAN、VXLAN、端口与链路。
5. 超融合和云桌面关系及容量展示。
6. 分类导入导出、全链路回归和原生界面验收。

每阶段必须保持可构建、可测试、可回滚；不得在中间阶段删除仍被旧页面使用的接口。

| AC-02 | 一级新增入口和筛选仅包含设备资源、业务系统、软件许可。 |
| AC-03 | 搜索覆盖编码、名称、SN、IP、品牌、型号、供应商和许可信息。 |

| AC-05 | 电脑和服务器可记录品牌、型号、CPU、内存、硬盘和操作系统。 |
| AC-06 | 网络和安全设备不显示 CPU、内存、硬盘、操作系统和 MAC。 |
| AC-07 | 虚拟资源和业务系统不显示物理品牌，并记录供应商。 |
| AC-08 | 软件许可记录授权量、已用量、到期日和分配关系。 |
| AC-09 | 设备接口实际联动 IPAM、VLAN 和可选 VXLAN VNI。 |
| AC-10 | 服务器和交换机可按具体端口记录上下联，首次建档不强制填写链路。 |
| AC-11 | 超融合集群、节点、云桌面平台、桌面池和终端关系可追溯。 |
| AC-12 | 云桌面终端分别记录并联动物理 IP 和虚拟桌面 IP。 |
| AC-13 | 分页、筛选、CRUD、调换、维修、归档、履历、导入导出能力完整保留。 |
| AC-14 | 导出全部匹配记录，不受当前页限制。 |
| AC-15 | 正式界面继续使用 Netcatty 原生组件、主题和图标，不引入 Ant 或 MUI。 |

## 18. 回滚边界

- 新表和新列采用向前兼容迁移，不通过回滚删除用户数据。
- 统一列表可回退到原领域列表，但数据库新增关系保持不动。
- 新增网络关系功能可独立关闭，不影响资产基础档案和 IPAM 原有数据。
- 每次数据库迁移前沿用现有备份机制；迁移失败停止写入并报告备份位置。
