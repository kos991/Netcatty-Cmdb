# 前台整体重建设计规范

## 1. 目标与边界

彻底重写前端的信息架构、页面布局和样式。保留 Go 后端、SQLite 数据库、现有 JSON 接口和已确认业务规则；旧 React 页面仅作字段、接口和操作流程对照，不作视觉或布局基础。

本轮只做三个一级入口：**全局查询、CMDB、IP 池**。统计数据可作为 CMDB 或 IP 池页面摘要，但不再占用独立一级入口。继续使用 React 18 + Ant Design 5，不引入复杂路由、全局状态框架、关系图或新的 UI 技术栈。

### 设计读法

这是面向法院信息技术人员的政务运维查询系统，不是营销页、作品集或炫技仪表盘。视觉参数固定为：**低变化、低动效、中高信息密度**。所有设计判断以“能否快速定位资产、看懂状态、完成操作”为准。

### 视觉基线

- 页面底色使用单一冷中性色，正文保持高对比度；全站只使用一个主强调色，状态色仅用于表达真实状态。
- 不使用渐变背景、玻璃拟态、装饰性光晕、无意义大标题或三张等宽宣传卡片。
- 采用统一的小圆角和细边框；列表优先用分隔线和留白，不把每块内容都包成卡片。
- 桌面端保证主要查询条件、关键字段和操作按钮同屏；移动端允许横向滚动表格，但不能遮挡操作列。
- 加载使用与最终布局一致的骨架或局部加载；空数据、接口错误、无权限和注销状态分别说明，不用通用空白或假成功提示。
- 所有按钮、输入框和状态标识检查文字对比度；图标只使用现有 Ant Design 图标，不手绘 SVG。

## 2. 信息架构

### 2.1 唯一顶栏

全站只保留一条顶部导航：

`常州中院资产台账` | `全局查询` | `CMDB` | `IP 池` | 在线状态 | 当前用户

禁止出现全高系统侧边栏、重复的顶部/左侧一级菜单或同级“工作台”。页面内部筛选使用页签、分段控件和工具栏；IP 网段选择属于 IP 池内部状态。

### 2.2 URL 状态

- `?view=search`
- `?view=cmdb&sub=assets|servers|apps|logs`
- `?view=ip_pool&sub=grid|ledger`

刷新后恢复当前入口和子页面；详情抽屉使用页面内状态。

## 3. 页面规范

### 3.1 全局查询

- 默认首页突出一个查询框，不堆叠营销式卡片。
- 查询范围覆盖终端资产、物理服务器、系统应用、运维履历和 IP 地址。
- 调用 `/api/search`，按实体分组展示名称、关键标识、状态和关联对象。
- 点击结果直接打开对应详情或定位 IP 单元格，不能只跳转到带关键词的列表。
- 任意页面支持 `Ctrl+K` / `Cmd+K` 聚焦；支持上下选择和回车打开。
- 空状态显示最近查询或真实数据摘要，避免无意义空白。

### 3.2 CMDB

CMDB 只使用顶部二级页签，不使用系统级侧栏：**云桌面终端、物理服务器、系统应用、全院运维履历**。

#### 云桌面终端

列表突出资产编码、盒子 SN、显示器 SN、使用人、部门、房间、业务 IP、终端 IP、安元状态和设备状态。保留查询、筛选、分页、字段选择、导出和批量操作。

行级操作保留新增、编辑、调换使用人、维修换件、履历、注销归档。注销为软注销，默认隐藏但可筛选查回；不能物理删除资产或历史履历。

详情使用右侧抽屉，包含基础信息、归属位置、网络信息、关联服务器/应用和完整履历；关联对象必须显示真实数据并可继续打开详情。

#### 物理服务器

独立列表和筛选条件，展示主机名、型号、机房位置、业务 IP、带外 IP、状态、责任人和应用数量。详情抽屉显示基础信息及应用列表，保留现有应用新增/编辑。

#### 系统应用

独立列表和筛选条件，展示应用名称、类型、所属服务器、端口、访问地址、中间件、数据库、负责人和状态。点击所属服务器打开服务器详情。

#### 全院运维履历

调用 `/api/logs`，按操作类型、时间、资产关键字和经办人筛选并分页。展示变更时间、资产、操作类型、变更前后、经办人和说明；点击资产打开详情并定位履历。

### 3.3 IP 池

IP 池页面内部不放系统级侧栏。

#### 网段选择

使用网段页签或分段控件，显示网段名称、容量、已用、空闲和保留数量。数量来自 `/api/ip_subnets`、`/api/ip_pool/summary`，不得写死。

#### 占用视图

首屏提供连续地址网格，让管理员一眼看到占用情况：绿色空闲、蓝色已占用、橙色保留/网关、红色异常或冲突。单元格 Tooltip 显示完整 IP、状态、使用人、部门、房间、关联资产和备注。

点击空闲地址打开分配表单；点击已占用地址打开详情，可释放、编辑或进入关联资产详情。网格只渲染接口实际返回的地址，无数据时明确提示，不伪造地址。

#### 地址台账

提供分页表格，支持按 IP、人员、房间、状态和网段筛选。保留新增、修改、分配、释放、删除和按当前筛选条件导出；导出不受当前页限制。

## 4. 联动契约

1. 全局查询结果携带实体类型和 ID，直接打开对应抽屉或定位 IP 单元格。
2. 资产详情展示实际 IP 关联；IP 状态变化以接口返回为准。若后端未提供级联释放，前端不得假装成功，应补齐调用或明确提示。
3. IP 池已占用地址存在资产 ID/编号时，点击直接打开资产详情；无明确关联时显示“未关联资产”。
4. 服务器详情展示真实应用列表；应用详情可打开所属服务器详情。
5. 调换、换件、编辑和注销完成后，资产详情和履历列表应能查到新记录。

## 5. 工程拆分

新增 `web/src/modules/`，与旧页面物理隔离：

```text
modules/
├── shell/TopHeader.jsx
├── search/GlobalSearch.jsx
├── cmdb/CmdbCenter.jsx
├── cmdb/AssetLedger.jsx
├── cmdb/ServerLedger.jsx
├── cmdb/AppLedger.jsx
├── cmdb/AuditLogsView.jsx
├── cmdb/AssetDrawer.jsx
├── cmdb/ServerDrawer.jsx
└── ippool/IPPoolCenter.jsx
```

`TopHeader` 只负责三个入口和在线状态；各台账页面负责自己的查询、分页、筛选和操作；详情抽屉负责关联数据展示和穿透。API 继续通过 `web/src/api.js`、`web/src/cmdb/cmdbApi.js` 调用，错误必须显式展示。新实现稳定前保留旧组件，最终验收后再清理未引用代码和依赖。

### 动效与 GSAP 工具边界

- 默认不使用页面转场、翻转、持续动画或 GSAP 时间线；政务内网台账优先保证首屏速度、稳定布局和可读性。
- IP 网格如果需要根据地址索引计算列、行或颜色，仅允许使用纯计算工具（如 `gsap.utils.clamp`、`mapRange`、`snap`），且封装在 IP 网格组件内，不把动画库扩散到全局。
- 任何 `gsap.utils` 使用必须有对应的真实 UI 需求和可测试输入输出；不能为了“有动效”引入依赖。
- 若新前端不再需要数值映射，实施阶段应移除 GSAP/Flip 依赖及相关注册代码。

## 6. 分阶段交付

1. 新壳层与全局查询：完成唯一顶栏、三个入口、URL 状态、搜索和结果穿透。
2. CMDB：完成终端、服务器、应用、履历四个子页及详情联动和原有业务操作。
3. IP 池：完成网段页签、实际数据驱动的占用网格、地址详情、分配/释放/修改/删除和导出。
4. 清理与回归：移除未引用旧前端入口和样式，确认数据和接口不受影响。

每阶段独立运行并提供真实截图，确认后再进入下一阶段。

## 7. 验收标准

| 编号 | 场景 | 合格标准 |
| --- | --- | --- |
| AC-01 | 导航 | 全站只有一条顶部一级导航，只有全局查询、CMDB、IP 池三个入口。 |
| AC-02 | 全局查询 | 可搜索五类实体，点击结果直接打开详情或定位 IP；`Ctrl+K` 在任意页面可用。 |
| AC-03 | CMDB 终端 | 查询、分页、筛选、增改、调换、维修、注销、履历、导出均可用。 |
| AC-04 | 服务器应用 | 服务器与应用独立查询，详情双向穿透，新增/编辑后列表立即可查。 |
| AC-05 | IP 占用 | 网格颜色与接口状态一致，点击地址可分配/释放/查看关联资产。 |
| AC-06 | 数据完整性 | 注销不物理删除；导出包含全部匹配记录；错误显式提示。 |
| AC-07 | 工程质量 | `npm.cmd run build`、`go test ./...` 通过；Playwright 检查桌面和移动端无异常、无重叠。 |

## 8. 回滚边界

不修改 Go 路由、SQLite 表结构和现有 API。新前端通过根组件入口切换；验收前保留旧组件，可回滚到原页面。需要新增后端联动时先确认接口能力，禁止前端伪造关联或成功状态。
