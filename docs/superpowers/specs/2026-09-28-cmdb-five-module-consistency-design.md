# Netcatty Cmdb 五模块功能与统一 UI 设计

## 1. 文档状态

- 日期：2026-09-28。
- 状态：五模块方向已确认；配置中心采用方案 A，删除“资产配置”。
- 适用范围：Netcatty 桌面客户端中的设备资产、组织架构、IPAM/IP、工单与统计、配置中心。
- 本文是后续原型、实施计划、代码修改和验收的统一基线。
- 本文不授权提交、推送、发布、修改版本号或修改正式 Netcatty 安装目录。

## 2. 决策优先级

本文按用户最新确认覆盖下列冲突旧设计：

1. 正式入口仅为 Netcatty 桌面客户端，不维护独立浏览器版。
2. Cmdb 一级导航固定为五个模块，不恢复独立“全局查询”。
3. 设备资产内部保留终端资产、基础设施和业务系统三个子页面。
4. 配置中心删除“资产配置”，只保留工单配置和项目设置。
5. 不恢复凭证中心、编码标签、软件安装情况和通用自定义属性界面。
6. Netcatty 集成界面使用宿主 React、Tailwind、Radix UI、Lucide 和 `components/ui`，不引入 Ant Design 或 MUI。

## 3. 产品目标

1. 五个模块使用同一套 Netcatty 原生视觉语言，但不强迫所有业务使用相同内容布局。
2. 主要操作、搜索、筛选、刷新、列表、详情和分页位置稳定，减少用户在模块间切换时重新学习。
3. 设备、人员、IP、业务系统、工单和 Netcatty 主机之间建立真实双向关系。
4. 所有业务数据属于当前项目，并进入既定的 Netcatty Cmdb 云同步路径。
5. 保留分页、CRUD、导入导出、注销归档、履历、调换、维修和关联能力。
6. 首次建档保持简单，复杂网络、连接和链路关系在资产保存后补录。

## 4. 非目标

- 不实现浏览器版、关系图、网络拓扑画布或复杂多级路由。
- 不实现资产自动扫描、Ping 探测、DHCP 或 DNS 管理。
- 不实现工单审批、SLA、派单或多人协作流程。
- 不建设通用低代码表单平台。
- 不复制 Netcatty 的主机库、身份库和密钥库。
- 不用配置项掩盖尚未实现的真实业务关系。

## 5. 统一 UI 设计系统

### 5.1 页面骨架

每个模块由以下区域组成：

1. Netcatty Cmdb 左侧一级导航。
2. 单一页头，包含主要操作、搜索、必要的次要操作和唯一刷新入口。
3. 模块专属筛选或视图切换区。
4. 可独立滚动的内容区。
5. 列表页面的固定分页区或工作台的固定保存区。
6. 按需打开的右侧详情工作区。

页面不得同时出现两个含义不同但图标相同的刷新入口。历史台账同步、云同步和数据导入必须使用完整文字，不得伪装为普通刷新。

### 5.2 密度和尺寸

- 页头最小高度 56px。
- 主要按钮高度 40px，表格工具按钮高度 32-36px。
- 搜索框根据窗口在约 360-620px 范围内伸缩。
- 表格正文使用 12-13px，表头和页面标题使用 12-14px。
- 普通表格行高约 40-44px。
- 设备详情默认占内容区约 48%-52%，支持最大化。
- 窄窗口优先切换为单栏或全宽详情，不产生页面级双重横向滚动。

### 5.3 视觉语义

- 主题、边框、背景、悬停和选中状态全部使用 Netcatty 主题变量。
- 暗色主题不得出现写死的白色、浅灰色或浅黄色信息块。
- 状态颜色只表达真实业务状态，不用于装饰。
- 同一语义只显示一次图标，品牌图标、系统图标和设备图标不得重复堆叠。
- 详情默认关闭，不能在进入模块时自动摊开资产档案。
- 加载、空数据、错误、无权限和关联对象失效分别展示明确状态。

### 5.4 统一操作规则

- 每页只有一个主要操作。
- 每页只有一个刷新当前页面入口。
- 导出使用当前全部筛选条件并导出全部匹配记录，不受当前页限制。
- 删除业务对象优先采用停用或注销归档；涉及历史和关系的数据不得物理删除。
- 保存失败必须保留用户输入并显示后端真实错误。

## 6. 模块一：设备资产

### 6.1 页面结构

页头依次放置：

1. “新增资产”下拉。
2. 三类资产统一搜索。
3. 弹性空白区。
4. “分类与分组管理”。
5. 唯一刷新按钮。

内容区使用紧凑选择器切换终端资产、基础设施和业务系统。各子页面保留自己的筛选、分页、模板、导入、导出和详情能力。

统一搜索覆盖资产编码、名称、SN、IP、品牌、型号和供应商。结果直接切换到相应子页面并打开详情，不替代子页面的高级筛选。

### 6.2 新增资产

“新增资产”只显示：

- 终端资产。
- 基础设施。
- 业务系统。

选择后打开右侧录入工作区。字段由资产类别和具体类型决定，不适用字段不显示。首次保存只要求最小必要字段；IPAM、VLAN、VXLAN、端口链路和 Netcatty 连接可在保存后补录。

### 6.3 终端资产

核心字段：资产编码、设备类型、品牌、型号、设备 SN、操作系统、设备 IP、IP 网络类型、使用人、组织归属、位置、状态、供应商和备注。

云桌面、云盒和盒子类型额外显示：

- 终端主机 SN。
- 显示器 SN。
- 终端物理 IP。
- 业务 / 虚拟机 IP。

普通物理终端只显示设备 SN 和设备 IP。切换为普通类型时清除不再适用的云桌面专属字段，但必须在保存前提示影响。

终端详情包含：

- 使用与位置。
- 设备与网络。
- 操作系统识别结果。
- 设备照片。
- Netcatty 连接。
- 运维履历。

终端详情不显示笼统的“关联信息”。保留调换使用人、维修换件、注销归档、导入导出和履历。

### 6.4 基础设施

基础设施类型至少支持服务器、虚拟机 / 云主机、交换机、路由器、安全设备、存储设备、超融合集群、超融合节点、云桌面平台和桌面池。

类型字段规则：

- 服务器显示品牌、型号、SN、CPU、内存、硬盘、操作系统、管理 IP、业务 IP 和带外地址。
- 虚拟机显示供应商、平台、实例标识、vCPU、内存、磁盘、系统、宿主机或集群，不显示物理品牌字段。
- 交换机、路由器和安全设备显示品牌、型号、SN、管理 IP、端口、供应商，不显示服务器 CPU、内存、硬盘、MAC 和普通操作系统字段。
- 存储设备显示品牌、型号、SN、总容量、磁盘配置、RAID 和管理 IP。
- 超融合和云桌面按平台、集群、节点、桌面池和终端关系展示专属字段。

基础设施完整列表使用以下列：

1. 资产名称 / 编码。
2. 分类 / 资产分组。
3. 型号 / 系统。
4. 负责人 / 组织。
5. 管理 IP。
6. 资产状态。
7. 操作。

“型号 / 系统”严格单行：

- 服务器示例：`[Lenovo] SR650 V3 / [Rocky] 9.4`。
- 交换机示例：`[H3C] S6520X`。
- 存储示例：`[Huawei] OceanStor 5310`。
- 虚拟机示例：`VMware VM / [Ubuntu] 22.04`。

CPU、内存、硬盘等完整配置进入详情，不在列表中增加第二、第三行。没有数据时显示“未录入”。

### 6.5 统一设备工作区

服务器、交换机、路由器、安全设备和存储共享：

- 固定标题栏和资产归属条。
- 管理 IP 快速连接。
- IPAM 和网络接口。
- 上联 / 下联关系。
- Netcatty 主机、身份和密钥引用。
- 照片、档案和履历。
- 编辑、克隆、注销归档。
- 半屏 / 最大化。

交换机专属区域包含端口面板、端口作用、PVID、允许 VLAN、聚合组、链路状态、ACL、账号权限、SSH / Telnet 状态和 SNMP 状态。

每台交换机选择一个主要读取方式：SSH、Telnet 或 SNMP。SSH / Telnet 可读取命令行配置、ACL 和账号权限；SNMP 读取系统、接口、VLAN 和状态。设备密码明文和不可逆密码哈希不得读取或展示。

服务器专属区域包含硬件系统信息、自动识别操作系统、承载业务系统、网络接口和 Netcatty 连接。路由器不展示尚未采集的路由表、NAT 或 VPN 假数据。

### 6.6 业务系统

业务系统字段包括名称、类型、版本、供应商、状态、负责人、组织、访问地址、协议、端口、中间件、数据库和说明。

“承载设备”统一改为“承载服务器”。候选对象来自基础设施中的服务器、虚拟机、云主机和超融合计算节点。交换机、路由器、安全设备、存储和终端不能作为承载服务器。

业务系统可关联一个或多个承载服务器。系统详情可以打开服务器详情；服务器详情反向展示承载的业务系统。

### 6.7 分类与分组管理

设备资产页头提供唯一入口：

- 资产分类表示设备是什么，使用树形结构。
- 资产分组表示项目内如何归类，使用列表结构。
- 支持搜索、新增、重命名、排序和停用。
- 被引用项只能停用，不能物理删除。

位置直接在资产表单录入，并提示当前项目中的历史位置值。厂商和型号在资产表单录入，自动匹配品牌图标和历史型号，不要求预先建立字典。

资产状态固定为在用、闲置、维修中、仓库备用和已归档。已归档由生命周期操作产生，不能在普通编辑表单中随意切换。

## 7. 模块二：组织架构

### 7.1 页面结构

页头包含新增人员、人员搜索、导入和导出。内容区左侧为约 240px 的组织树，右侧为人员列表和分页。窄窗口将组织树收进抽屉。

### 7.2 组织规则

- 每个项目一个根机关单位。
- 支持任意层级，不固定组织、部门、分组三级。
- 支持机关单位、内设机构、部门、科室、派出机构、办事处和自定义节点类型。
- 不存在工作组、邮箱、多正式部门或矩阵组织。
- 节点支持新增下级、编辑、移动和停用。
- 根节点不能删除、移动或停用。
- 停用节点不能接收新人员、资源或下级节点。
- 节点类型管理位于组织架构模块内部，不进入配置中心。

### 7.3 人员规则

人员字段包括人员编号、姓名、唯一正式归属节点、职务 / 岗位、联系电话、状态和备注。

人员详情显示基础档案、完整组织路径、名下设备、负责的业务系统、调动履历和资产批量交接入口。关联资源可以继续打开对应档案。

### 7.4 拖拽

- 人员行提供拖拽手柄。
- 支持单人和勾选后的批量拖拽。
- 可接收目标节点高亮。
- 停用节点和“未归属”虚拟节点不能作为目标。
- 拖放后直接完成调动，不建设审批流。
- 人员及其明确绑定的责任资源在同一事务中更新，失败整体回滚。
- 人员调动和资源归属变化分别写入履历。

## 8. 模块三：IPAM/IP

### 8.1 页面结构

页头包含新增网段、统一搜索、模板、导入、导出和唯一刷新。内容区左侧为约 224px 的网段列表，右侧使用“IP 地址 / VLAN / VXLAN”分段切换。

顶部展示当前网段摘要和使用率，下方展示筛选、图例和约 12 列的紧凑地址网格。地址详情按需在右侧打开。

### 8.2 地址网格

- `/24` 默认每页 96 个地址。
- 地址块高度约 36px，只显示主机位数字。
- 完整 CIDR 始终显示在网段摘要中。
- 网络地址和广播地址明确显示为只读，不允许预留或分配。
- 空闲和保留使用中性色。
- 设备占用、应用占用、共同占用和冲突使用明确状态色，不使用图标。
- 选中地址只增加主题边框，不增加另一套背景和阴影。

### 8.3 状态和统计

地址最终状态由真实关系计算：空闲、保留、设备占用、应用占用、共同占用和冲突。多个应用共享一个 IP 合法；两个不同设备占用同一 IP 默认冲突。

网段摘要显示 CIDR、网络类型、网关、网络地址、广播地址、VLAN、VNI、使用率、设备占用、应用占用、共同占用、空闲、保留和冲突。

使用率按唯一占用 IP 数计算，设备与应用共同占用不得重复计数。

### 8.4 分配与联动

空闲或预留 IP 可分配给设备或业务系统：

- 设备分配选择设备、接口、IP 用途和 VLAN / VXLAN。
- 应用分配选择业务系统、用途、协议、端口和可选承载服务器。
- 保存成功后资产和业务系统档案立即显示关系。
- 地址释放按设备接口或应用端点逐项解除。
- 管理 IP 关联 Netcatty 主机后可直接发起连接。
- 写入任一关系失败时整笔事务回滚。

VLAN 和 VXLAN 支持项目隔离的搜索、分页、新增、编辑、停用、导入、导出和引用保护。不实现网段扫描。

## 9. 模块四：工单与统计

### 9.1 默认工作台

模块默认进入“新建工单”。页头下拉只切换“新建工单”和“工单统计”。

桌面宽度下采用左侧约 312px 当日工单区、右侧新建或详情区：

- 左侧提供日期、日历、搜索、筛选、当日工单和分页。
- 右侧直接显示新建表单，不使用弹窗。
- 点击左侧工单后，右侧原位显示详情和编辑。
- 右侧表单最大内容宽度约 920px，不随大窗口无限拉宽。
- 窄窗口使用“工单列表 / 新建工单”切换，不并排挤压。

### 9.2 新建工单

固定字段包括工单编号、当前项目、工单类别、优先级、发生时间、运维类型、经办人、工时、主题、处理内容、处理结果、关联资源和附件。

- 工单编号不可手填，由当前项目规则在创建时生成。
- 当前项目只读。
- 不使用“通用工单”名称；默认类别由配置中心指定。
- 发生时间默认当前时间并允许修改。
- 经办人首次选择后按项目记忆。
- 关联资源可搜索、多选或不选，范围包含三类资产。
- 附件可在创建前选择，工单创建后按顺序上传。
- 不建设审批、派单、SLA 或多人流程。

工单类别可附带少量专属字段，只支持单行文本、多行文本、日期时间、数字和单选，不建设通用低代码平台。

### 9.3 工单统计

统计筛选支持日期范围、关键词、类别、运维类型、优先级、状态、结果、经办人、组织、资产类型、指定资产、是否关联资产、是否有附件和工时范围。

统计展示总数、类别、运维类型、状态、经办人工作量、工时汇总和筛选后的明细。XLSX 导出包含“统计汇总”和“工单明细”，并导出全部匹配记录。

## 10. 模块五：配置中心

### 10.1 职责边界

配置中心采用方案 A，删除“资产配置”一级分组，只保留：

1. 工单配置。
2. 项目设置。

配置中心不得重复提供资产分类、设备类型、资产分组、组织架构、位置目录、厂商型号、通用扩展字段、凭证中心、编码标签或软件安装情况。

### 10.2 统一 UI

配置中心继续使用与其他四个模块相同的页头高度、字体、搜索和按钮规范：

- 页头左侧显示“配置中心”和当前项目。
- 一级切换只显示“工单配置”和“项目设置”。
- 次级页面只在业务确有多个平级设置时显示紧凑页签。
- 设置表单使用与资产工作区一致的字段、间距、错误提示和固定保存区。
- 目录表格使用与其他模块一致的行高、空状态、操作图标和确认窗口。
- 不使用独立的卡片风格、超大标题、不同圆角或额外颜色。

### 10.3 工单配置

工单配置包含：

- 编号规则。
- 工单类别。
- 运维类型。
- 优先级。

编号规则支持前缀、分隔符、日期段、流水号位数、重置周期和下一编号预览。工单类别支持名称、排序、默认优先级、默认运维类型、启用状态和简单专属字段。被历史工单引用的配置只能停用。

### 10.4 项目设置

项目设置按同一滚动页面分区：

1. 项目资料：项目名称、项目编码和当前项目标识。
2. 附件存储：当前路径、选择目录、打开目录、附件数量和空间占用。
3. Netcatty 云同步：开关、同步范围、最近结果和立即同步。
4. 数据维护：同步历史台账、导入项目数据和导出项目迁移包。

“同步历史台账”使用文字按钮，执行前展示数据来源、预计新增、更新和冲突数量，二次确认后执行，并显示真实结果。它不得出现在设备资产工具栏中，也不得继续使用刷新图标。

## 11. 跨模块联动

- 人员详情可以打开名下资产。
- 资产详情可以打开对应 IPAM 地址。
- IPAM 地址可以打开占用设备或业务系统。
- 业务系统可以打开承载服务器。
- 服务器可以反向查看承载的业务系统。
- 工单关联资源可以打开对应档案。
- 管理 IP 可以调用 Netcatty 原生连接。
- 分类、状态和工单配置变更后，业务页面重新加载真实配置。
- 所有查询、写入、导入、导出、同步和关联必须使用当前项目上下文，不得默认取项目列表第一项。

## 12. 数据同步和交换

Cmdb 业务数据以独立规范快照进入 Netcatty 现有加密同步载荷。同步范围包括项目、资产、组织、人员、IPAM、业务系统、工单、配置和关系数据。

附件二进制、本机绝对路径、密码、私钥和令牌不进入 Cmdb 快照。Cmdb 只同步 Netcatty 主机、身份和密钥的稳定引用，不复制秘密内容。

终端资产、基础设施、业务系统、组织人员、IPAM 和工单分别提供模块级导入导出。配置中心的数据维护提供完整项目迁移包。正式发布包不得包含演示业务数据。

## 13. 错误和回滚边界

- 项目、资产、人员、IP、VLAN、VXLAN、工单和关联对象必须属于同一项目。
- 关联失败不得用自由文本或状态字段伪造成功。
- 资产归档保留履历、IP、链路和工单关系，默认列表隐藏。
- 被引用的分类、组织节点、工单类别、VLAN 和 VXLAN 只能停用或拒绝删除。
- 新增表和列采用向前兼容迁移，不通过回滚删除用户数据。
- 各模块界面可以独立回退，但新关系数据必须继续可读。

## 15. 验收标准

### 15.1 全局

- 五个模块使用同一页头、字体、按钮、搜索、表格、详情和错误反馈规范。
- 不依赖 Ant Design 或 MUI。
- 深色和浅色主题无写死白色区域。
- 1366x768 和当前桌面窗口下无页面级横向溢出。
- 页面只有一个刷新当前页面入口。
- 当前项目贯穿查询、写入、导入、导出和同步。

### 15.2 设备资产

- 保留终端资产、基础设施和业务系统三个子页面。
- 基础设施“型号 / 系统”严格单行且按类型展示。
- 终端、网络、安全、存储、虚拟机、超融合和云桌面字段不互相污染。
- 管理 IP 可以关联并调用 Netcatty 主机连接。
- 分类和分组只有一个管理入口。

### 15.3 组织架构

- 支持根机关单位、任意层级、办事处和自定义节点类型。
- 不出现工作组、邮箱和固定三级归属。
- 单人和批量拖拽事务更新人员与责任资源并记录履历。

### 15.4 IPAM/IP

- 网格只显示主机位数字，网络地址和广播地址不可分配。
- 能区分设备、应用、共同占用、空闲、保留和冲突。
- 使用率不重复计数。
- 分配与释放在资产、应用和 IPAM 间双向一致。

### 15.5 工单与统计

- 默认进入左侧当日工单、右侧新建工单的工作台。
- 工单编号自动生成，经办人按项目记忆，关联资源可多选或不选。
- 创建前可选择附件，创建后正确上传。
- 统计支持多维筛选和全部匹配记录导出。

### 15.6 配置中心

- 一级分组只有工单配置和项目设置。
- 不出现资产配置、凭证中心、编码标签和软件安装情况。
- UI 与其他模块使用同一页头、控件、密度和反馈规范。
- 历史台账同步位于项目设置的数据维护区，并具有预览、确认和结果反馈。
