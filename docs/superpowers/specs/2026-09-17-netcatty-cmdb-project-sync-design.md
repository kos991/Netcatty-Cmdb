# Netcatty Cmdb 项目化、云同步与数据交换设计

## 1. 文档状态

- 状态：已完成方案确认，待用户审阅本文档后进入实施计划。
- 目标版本：`v1.3.0`。
- Netcatty 基线：`v1.1.83`，提交 `d7a0c8ed8d238dcf1c82d786da53037a1f1496b1`。
- 本设计替代 `2026-09-16-netcatty-native-cmdb-design.md` 中以下内容：
  - 用户可见名称 `CMDB 资产管理` 改为 `Cmdb`。
  - Cmdb 内部的横向六模块导航改为 Netcatty 原生工作区侧栏。
  - “不新增配置中心”的限制取消，新增业务所需的配置中心。
  - 发布包不再包含业务初始化数据。

## 2. 背景与问题

当前 Cmdb 已作为 Netcatty 原生根标签运行，但仍存在以下结构性问题：

1. 组织、部门和分组来源不统一。人员表单使用自由文本，左侧组织树由现有人员临时聚合，空组织无法显示，也无法独立维护。
2. 设备类型、终端状态、软件安装情况和部分位置字段仍为硬编码或自由文本，缺少统一配置入口。
3. 终端页面仍使用“云桌面盒子 SN”“房间/法庭”“安元软件”等固定业务文案。
4. IP 方格的空闲与占用主要依赖文字颜色，底色和形态接近，无法快速辨识。
5. Cmdb 内部视觉和导航仍像嵌入的网页后台，与 Netcatty 主机、钥匙串工作区不一致。
6. 所有资产缺少统一的项目归属，Cmdb 资产、Netcatty 主机与钥匙串之间没有稳定关系。
7. `assets.db` 虽位于 Netcatty 用户数据目录，但没有进入 Netcatty 云同步载荷；同目录不等于已同步。
8. 发布程序内嵌 `seed/seed_v2.json`，全新数据库会自动导入业务资产、人员相关信息、IP、服务器、应用和履历。
9. 导入导出能力不完整：基础设施已有通用导入导出，终端资产和 IP 主要只有导出，业务系统只有特定来源导入，组织人员缺少标准数据交换能力。

本轮不再逐页修补。项目归属、主数据配置、云同步、导入导出和 Netcatty 关联必须使用同一套数据契约实现。

## 3. 目标与非目标

### 3.1 目标

1. 所有 Cmdb 业务数据必须归属于一个项目；首期至少存在一个默认项目。
2. Cmdb 使用 Netcatty 原生工作区布局、主题变量、交互密度和 Lucide 图标。
3. 用户可见根标签统一为 `Cmdb`，不再显示 `CMDB 资产管理`、`CMDB 资产管`或同类组合名称。
4. 组织、部门、分组、设备类型、软件目录、位置、厂商型号和状态展示配置均有真实管理入口。
5. Cmdb 资产能够关联 Netcatty 主机和钥匙串引用，并可从资产发起原生连接。
6. Cmdb 项目数据接入 Netcatty 现有云同步账户、主密钥、同步按钮和状态反馈。
7. 所有主要业务模块提供标准导入导出；另提供项目级完整迁移包。
8. 正式发布包首次启动必须为空库，不得携带任何真实或演示业务数据。
9. 现有数据库升级前自动备份，迁移失败必须保持原库可用。

### 3.2 非目标

- 不直接把 SQLite 数据库文件上传到云端。
- 不把 Cmdb 表并入 Netcatty 自身数据库。
- 不复制、读取或导出钥匙串中的密码、私钥、令牌等秘密内容。
- 不引入 MUI、ORM、FTS、缓存、关系图或新的全局状态框架。
- 不使用“导入文件中不存在即删除”的危险同步语义。
- 不在本轮提供多人实时协同编辑或中心服务器锁服务。
- 不自动删除已经发布的 `v1.2.0` Release，也不自动重写 Git 历史；此类破坏性处置需单独授权。

## 4. 核心架构决策

### 4.1 一个产品入口，两个本地存储边界

Cmdb 与 Netcatty 在产品层面共用项目上下文、云同步入口和关联关系，但保留独立本地存储：

```text
Netcatty Electron
├── Netcatty Vault 数据库 / 本地存储
│   ├── 主机
│   ├── 钥匙串与身份
│   └── 连接设置
└── Cmdb Go 服务
    └── userData/assets.db
        ├── 项目与配置
        ├── 资产、人员、IP、应用
        ├── 关联关系
        └── 运维履历
```

继续沿用 `assets.db` 文件名，避免无业务收益的路径迁移。渲染器不能直接访问数据库，仍通过 preload IPC 和 Go API 调用。

### 4.2 同一同步操作，独立加密对象

不把完整 Cmdb 数据塞入现有 Vault 单文件，也不上传 `assets.db`。Netcatty 同步管理器在一次同步操作中协调：

```text
Netcatty Vault 加密对象
Cmdb 项目索引加密对象
Cmdb 项目 <project_sync_id> 加密对象
```

三类对象使用相同的：

- 云服务提供方和账户；
- Netcatty 主密钥派生的加密密钥；
- 加密对象存储接口；
- 同步锁、读取、合并、写入、回读验证和历史记录；
- 用户触发的“立即同步”和自动同步调度。

Cmdb 对象使用独立命名空间，避免任意一条资产变更都导致整个 Vault 重新上传。同步页面只呈现一个入口，但必须分别报告 Vault 和各 Cmdb 项目的结果，部分失败不能显示为整体成功。

### 4.3 云同步不是备份，也不是 Excel 导入

- 云同步：用于同一用户的多设备持续收敛。
- 项目迁移包：用于完整迁移、离线交付和灾难恢复。
- Excel/CSV：用于业务批量录入、核对和人工交换。
- 本地数据库备份：用于迁移或恢复失败时回滚。

四者必须使用独立入口和提示，不能用一个“导出”按钮混淆职责。

## 5. 项目模型

### 5.1 项目实体

新增 `cmdb_projects`，至少包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 本地 SQLite 主键 |
| `sync_id` | 跨设备稳定 UUID |
| `code` | 项目编码，同一数据集唯一 |
| `name` | 项目名称 |
| `status` | `active` 或 `archived` |
| `is_default` | 是否默认项目 |
| `revision` | 本地同步修订号 |
| `created_at` / `updated_at` | 创建和更新时间 |
| `deleted_at` | 同步删除墓碑；项目默认只归档，不提供普通物理删除 |

首次升级自动创建一个默认项目，并把现有业务数据归入该项目。默认项目名称可修改，但 `sync_id` 不得变化。

### 5.2 项目归属范围

以下数据必须具有 `project_id` 和稳定 `sync_id`：

- 组织、部门、分组、人员；
- 终端资产、服务器、基础设施资产；
- 业务系统及承载关系；
- IP 网段、IP 地址和分配关系；
- 设备类型、设备模型、位置和软件目录；
- 软件安装记录；
- 资产与 Netcatty 主机、钥匙串引用；
- 资产履历、工单、盘点、标签等项目业务数据。

自增 `id` 只用于单机内部查询。所有跨设备、导入包和关联关系必须使用 `sync_id`，禁止依赖自增 ID。

### 5.3 现有重复资产投影

当前终端、服务器等源表会映射到 `cmdb_assets`。云同步和项目导出不得把源记录与派生投影重复传输。

便携数据层按以下规则生成规范记录：

- `assets` 是终端资产的业务源。
- `servers` 是现有物理服务器业务源。
- `server_apps` 是现有业务系统源。
- `cmdb_assets` 中 `source_type` 为空或为手工登记的记录作为原生基础设施源。
- `cmdb_assets` 中来自旧台账映射的记录只同步其 Cmdb 专属覆盖字段，不重复同步源资产主体。
- 恢复或同步应用后，继续调用现有幂等映射逻辑重建统一查询投影。

该规则避免为云同步立即重写全部业务接口，同时保证同一资产不会在另一台设备生成两份。

### 5.4 Netcatty 主机和钥匙串的项目范围

- 每项 Cmdb 资产必须属于一个项目，不允许无项目资产。
- Netcatty 主机在未关联 Cmdb 时可以暂时不归属项目；关联资产后自动继承该资产的项目。
- 同一主机不能同时作为不同项目资产的主连接。需要跨项目使用时，只允许作为显式共享连接并显示共享标记。
- 钥匙串条目不复制到项目数据库。其可用范围为“仅当前项目”或“共享”，由 Netcatty 持有并同步。
- 现有 Netcatty 主机升级后保持可用，不强制批量改写；用户关联资产或批量分配项目时再补充项目引用。

## 6. 配置与业务术语

### 6.1 组织与人员

组织树必须来自真实配置表，不再根据人员记录临时聚合。

- 组织、部门采用可排序树形结构。
- 分组作为项目内独立维度，可关联组织或部门。
- 无人员的组织和部门仍须显示。
- 人员表单中的组织、部门、分组使用 ID 下拉和级联过滤，不使用自由文本。
- 删除配置前检查人员和资产引用；存在引用时拒绝删除并显示数量。
- 人员选择器用于资产编辑和调配，并自动带出组织、部门和分组。

### 6.2 设备类型

设备类型改为项目内可管理的树形目录。系统只提供空结构和必要代码约束，不内置法院业务数据。

建议初始结构由用户创建或导入：终端主机、显示器、物理服务器、虚拟机、交换机、路由器、安全设备、存储设备和其他设备。

列表、筛选、新增、编辑和导入均引用设备类型 ID。旧字段继续作为兼容字段，但不再作为新的配置来源。

### 6.3 软件目录与安装记录

移除固定“安元软件情况”选择器，建立：

- 软件目录：名称、厂商、类别、版本、启用状态和备注。
- 资产软件安装记录：资产、软件、安装状态、安装版本、检查时间和备注。

安元可以由用户添加为普通软件。资产可登记多个软件，统计页面按用户选定的软件计算覆盖率。

### 6.4 位置与状态

- 位置目录统一维护办公区、房间、仓库、数据中心、机房、楼层和机柜等层级。
- 调配流程使用“当前位置”“新位置”，删除“法庭”固定文案和示例。
- 状态保留稳定系统代码，展示名称、排序和颜色可配置。业务逻辑只判断代码，不能依赖用户修改后的中文名称。

### 6.5 文案统一

全系统用户可见文案统一：

| 旧文案 | 新文案 |
| --- | --- |
| `CMDB 资产管理` | `Cmdb` |
| 云桌面盒子 SN / 盒子 SN | 终端主机 SN |
| 更换云桌面盒子 | 更换终端主机 |
| 房间/法庭、新房间/法庭号 | 位置、新位置 |
| 安元软件情况 | 已安装软件 |

终端、服务器、应用、统计、导入导出表头、履历和使用说明中的固定法院业务示例一并清理。

## 7. Netcatty 主机和钥匙串关联

### 7.1 关联表

新增项目内关联记录：

```text
cmdb_asset_host_links
  project_id
  sync_id
  asset_sync_id
  netcatty_host_id
  relation_type
  is_primary
  created_at / updated_at / deleted_at

cmdb_asset_credential_links
  project_id
  sync_id
  asset_sync_id
  credential_ref_type
  credential_ref_id
  purpose
  created_at / updated_at / deleted_at
```

`credential_ref_type` 只允许 Netcatty 已支持的身份或钥匙引用类型。Cmdb 不保存秘密值，也不通过 API 返回秘密值。

### 7.2 业务规则

- 一项资产可关联多个主机连接，其中最多一个主连接。
- 一个 Netcatty 主机默认只能作为一项资产的主连接；重复绑定必须提示冲突。
- 资产注销只解除或停用关联，不删除 Netcatty 主机和钥匙串。
- 主机或钥匙串不存在时保留引用并显示“待关联”或“凭据不可用”，不能静默删除。
- 从资产新建主机时预填名称、地址、端口、协议、项目和资产引用。
- 从资产点击“连接”时调用 Netcatty 原生连接流程，由 Netcatty 自行解析钥匙串和身份。
- 关联、新建、解除和引用失效均写入 Cmdb 运维履历，但履历不得记录秘密。

### 7.3 同步顺序

跨设备恢复时按以下顺序应用：

1. Netcatty 主机、身份和钥匙串。
2. Cmdb 项目与基础配置。
3. Cmdb 业务实体。
4. 资产与主机、钥匙串引用。
5. 完整性校验和待关联提示。

## 8. 云同步协议

### 8.1 可同步数据

同步项目、配置、业务实体、关联关系、运维履历和删除墓碑。运维履历采用追加式记录，以 `sync_id` 去重；正常 UI 不提供修改历史履历。

不进入云同步：

- SQLite 文件本体、WAL 和临时文件；
- 密码、私钥、令牌等秘密明文；
- Go 服务端口、PID、日志和健康状态；
- 在线探测缓存、连接会话、窗口状态和最近活动；
- 导入临时文件、导出文件和本地备份。

### 8.2 收集与应用接口

Go 服务提供仅供 Electron 主进程调用的同步接口：

- 导出项目规范快照和摘要哈希；
- 预检远端快照，返回新增、修改、删除和冲突统计；
- 在单个 SQLite 事务内应用已确认快照；
- 应用后返回新摘要，供 Netcatty 回读验证。

这些接口继续由现有回环服务和 IPC 白名单保护，渲染器不能指定数据库路径或云端对象键。

规范快照至少包含：

```text
schema_version
project_sync_id
generated_at
base_hash
collections
tombstones
```

`collections` 只包含跨设备 UUID 和业务字段，不包含 SQLite 自增 ID、文件路径或秘密。Netcatty 为每个项目保存可信合并基线，Go 服务只负责生成和事务应用规范数据，不自行连接云端。

### 8.3 加密与云端对象

- 明文规范快照只存在于受控内存和本机 IPC 调用期间。
- Netcatty 主进程使用现有主密钥派生机制和 AES-GCM 加密后写入云端。
- 项目索引使用 `cmdb/index/v1` 对象键；每个项目使用 `cmdb/projects/<project_sync_id>/snapshot/v1` 对象键和独立版本元数据。
- 云端提供方只接收密文，不接收主密钥和明文项目数据。
- Cmdb 同步开关位于 Netcatty 同步设置中，首次启用必须明确确认。
- 可单独关闭人员联系方式和运维履历同步；关闭时字段或集合必须稳定省略，不能被解释为远端删除。

### 8.4 合并和冲突

复用 Netcatty 现有同步锁、可信基线、保护快照、收敛合并、回读验证和可疑大规模删除保护。Cmdb 数据按稳定 `sync_id` 合并，删除使用墓碑传播。

以下场景不能用简单最后写入覆盖，必须产生待处理冲突：

- 同一项目内一个 IP 被分配给不同资产。
- 资产编码、人员工号或项目编码发生唯一性冲突。
- 一个 Netcatty 主机被绑定为多个资产的主连接。
- 两端同时修改同一记录的同一关键字段。
- 远端关系引用本地不存在且云端也未包含的项目、资产、人员、主机或钥匙串。

同步结果页面必须展示：本地新增、远端新增、修改、删除、冲突、未解析引用和每个云端对象的写入验证结果。

### 8.5 失败处理

- 应用远端数据前创建数据库安全备份。
- 项目快照在一个数据库事务内应用，任一校验失败则全部回滚。
- 部分项目同步失败时，已验证成功的对象不伪装成整体成功；失败项目保持待同步状态。
- Netcatty Vault 同步成功但 Cmdb 失败时，界面分别显示两者状态。
- 中断或崩溃后根据摘要和同步历史安全重试，不重复创建业务记录。

## 9. 导入导出

### 9.1 模块级业务交换

| 模块 | 导入 | 导出 |
| --- | --- | --- |
| 终端资产 | XLSX 模板、预览、事务提交 | 当前筛选全部、选中记录、全部记录 |
| 基础设施资产 | XLSX/CSV 模板、预览、事务提交 | 当前筛选全部、选中记录、全部记录 |
| 业务系统 | 系统、承载资产和端口关系模板 | XLSX/CSV |
| 组织与人员 | 组织路径、部门、分组和人员模板 | XLSX |
| IP 规划池 | 网段与地址模板 | XLSX/CSV |
| 软件目录 | 软件目录与资产安装关系模板 | XLSX |
| 设备类型、位置、模型 | 配置模板 | XLSX |
| 运维履历 | 普通业务导入不开放 | 只读 XLSX/CSV 导出 |

所有导出默认限定当前项目。列表导出必须使用当前筛选条件导出全部匹配记录，不受当前页限制。

### 9.2 导入流程

固定流程：

```text
下载模板 -> 选择文件 -> 解析预览 -> 错误清单 -> 选择模式 -> 确认写入
```

导入模式只提供：

- 仅新增；
- 新增并更新匹配记录。

默认不因导入文件缺少某条记录而删除数据库内容。每次提交在单个事务内完成，并在提交前创建本地备份。

### 9.3 匹配规则

| 实体 | 默认匹配键 |
| --- | --- |
| 资产 | 项目编码 + 资产编码 |
| 人员 | 项目编码 + 工号 |
| IP | 项目编码 + 网段 + IP |
| 业务系统 | 项目编码 + 系统编码 |
| 软件 | 项目编码 + 软件名称 + 厂商 |
| 组织节点 | 项目编码 + 完整组织路径 |

人员没有工号时不得仅按姓名自动覆盖；资产没有资产编码时不得仅按名称自动合并。需要人工确认的记录在预览中标记。

### 9.4 项目完整迁移包

项目迁移包扩展名为 `.netcatty-cmdb`，包含版本化清单、规范数据、关联关系、履历和 SHA-256 校验，不包含秘密内容。

```text
manifest.json
projects.json
taxonomy.json
persons.json
assets.json
applications.json
ip-pools.json
software.json
relations.json
audit-logs.json
checksums.json
```

迁移包默认由 Netcatty 主进程加密。离线跨账户迁移时要求用户设置导出密码，密码不保存。普通 XLSX/CSV 属于用户明确选择的明文业务文件，保存前显示敏感数据提示。

项目包恢复必须先预览版本、数量、冲突和无法解析的主机/钥匙串引用，再允许提交。普通导入不能写入历史履历；只有项目恢复可以恢复履历。

## 10. 原生界面设计

### 10.1 Netcatty 根标签

固定根标签名称为 `Cmdb`，使用 Netcatty 已有 Lucide `Database` 图标、相同的 14px 尺寸、描边和选中状态。窗口标题和活动标签说明同样使用 `Cmdb`。

### 10.2 Cmdb 工作区

Cmdb 根标签内部使用与 Netcatty 主机工作区一致的布局：

```text
左侧原生工作区侧栏         右侧主工作区
├── 当前项目               标题 / 搜索 / 主要操作
├── 设备资产               筛选工具栏
├── 组织架构               终端资产 / 基础设施 / 业务系统
├── IPAM/IP                数据列表、网格或详情
├── 统计与履历
└── 配置中心
```

- 左侧一级入口固定为“设备资产、组织架构、IPAM/IP、统计与履历、配置中心”，“设备资产”是默认首页。
- 设备资产内部保留“终端资产、基础设施、业务系统”三个子页面；统一搜索位于设备资产顶部，不再设置独立全局查询入口。
- 左侧侧栏复用 Netcatty 的背景、选中行、图标、字号、间距和折叠行为。
- 项目选择器位于侧栏顶部；首期只有一个项目时仍显示项目名称，不强制展示无意义下拉箭头。
- 正式界面源码集中在 `integrations/netcatty/cmdb/`，直接引用 Netcatty `components/ui`、Tailwind、Radix UI 和 Lucide；`web/` 只作为迁移期业务行为参考。
- 表格、筛选、分页、表单、弹层、通知、加载和空状态均使用 Netcatty 原生组件或基于相同 token 的 Cmdb 领域组件，不保留 Ant API 兼容层。
- `scripts/prepare-netcatty.mjs` 只装配原生 Cmdb 源码和 Electron 集成，不向 Netcatty 注入 `antd`、`@ant-design/icons`、`@ant-design/v5-patch-for-react-19` 或 `dayjs`。
- 独立浏览器版停止维护，产品只保留 Netcatty 原生客户端入口。
- 亮色和深色模式均由 Netcatty 宿主主题驱动。

### 10.3 IP 占用视图

空闲和占用必须同时依靠底色、边框、形态和文字区分，不能只依赖红绿数字：

| 状态 | 表现 |
| --- | --- |
| 空闲 | 浅绿色底、绿色边框、圆点标记 |
| 已占用 | 蓝色或深灰蓝底、明显边框、主机或锁定标记 |
| 保留 | 橙色底、橙色边框 |
| 冲突/异常 | 红色底、警告图标 |
| 不可分配 | 灰色斜线纹理 |

图例使用完整状态标签和数量。点击已占用地址打开详情或关联资产；点击空闲地址进入分配。悬停展示完整 IP、状态、资产、使用人、位置和备注。

### 10.4 配置中心

配置中心包含：

- 组织、部门与分组；
- 设备类型；
- 软件目录；
- 位置目录；
- 状态展示配置；
- 厂商与设备模型；
- 项目设置。

已有分类管理和设备模型组件应迁入该入口复用，不重复实现一套页面。

### 10.5 资产连接区

资产详情新增“连接与凭证”区：

- 展示关联主机名称、协议、地址、状态和是否主连接；
- 提供“连接”“查看主机”“关联已有主机”“新建主机并关联”；
- 展示钥匙串引用名称、类型和可用状态，不展示秘密值；
- 未同步或已删除的引用显示明确状态和修复入口。

Netcatty 主机编辑或上下文菜单提供“关联 Cmdb 资产”“查看关联资产”“解除关联”。

## 14. 测试策略

### 14.1 后端和迁移

- 全新库只包含空默认项目，其他业务表为零。
- 旧库迁移前创建备份，迁移后记录数和关键字段不丢失。
- 重复执行迁移不产生重复项目、UUID 或关联记录。
- 项目隔离覆盖列表、详情、搜索、导出和统计。
- 导入预览不写库；提交失败整体回滚。

### 14.2 导入导出

- 每种模板均做生成、解析和往返测试。
- 当前筛选导出数量等于全部匹配数量，不受分页影响。
- 重复导入按匹配规则新增或更新，不产生意外重复。
- 项目包校验和、版本检查、错误引用和密码错误均有测试。
- Excel、CSV 和项目包均不包含钥匙串秘密。

### 14.3 云同步

- 设备 A 创建、设备 B 拉取。
- 两端修改不同记录可收敛。
- 两端修改同一关键字段产生冲突。
- 删除墓碑传播且不会被旧设备复活。
- 同一 IP 双重分配产生阻断冲突。
- Vault 成功但 Cmdb 失败时显示部分失败。
- 写入后回读不一致时保持待同步并保留本地数据。
- 缺少主机或钥匙串时保留待关联引用。

### 14.4 原生界面

- 2026-09-18 界面原型确认采用 A“原生工具栏”方案：设备资产使用 Netcatty `VaultPageHeader` 与 `VaultHeaderSearch`，默认搜索宽度 420px，列表使用紧凑原生表格；IP 地址块默认 92×42px。
- 基础设施界面不显示地理扩展、电力规格、其他信息和自定义属性；旧数据库字段仅为兼容历史数据保留。
- 亮色、深色模式与 Netcatty 原生控件一致。
- 装配后的 Netcatty `package.json` 不含 Cmdb 引入的 Ant Design 依赖，Cmdb 可达源码不含 `antd`、`@ant-design/icons` 和 `ConfigProvider`。
- 根标签只显示 `Cmdb`，内部无重复横向一级导航。
- 所有 Cmdb 图标来自 Netcatty 的 Lucide 图标体系。
- 空闲、占用、保留、冲突和不可用 IP 在不阅读图例时也能辨识。
- 组织、人员、类型、软件和位置管理流程可闭环。
- 资产详情可连接关联主机，但不能查看任何钥匙串秘密。

- `go test -count=1 ./...`。

| 编号 | 合格标准 |
| --- | --- |

| AC-03 | 组织、部门、分组可独立维护，人员使用级联下拉选择。 |

## 16. 回滚边界

- 每次数据库结构迁移和远端数据应用前创建本地备份。
- 新字段和新表采用向前兼容迁移，不通过降级删除列或清空数据。
- 云同步可在设置中停用；停用只停止上传下载，不删除本地或云端数据。
- 原生 UI 和桥接补丁集中在集成层，可回滚界面而不回滚业务数据库。
- 导入失败依靠事务回滚；项目恢复失败依靠事务和恢复前备份回滚。
- 已发布 Release 删除、远程数据删除和 Git 历史重写不属于普通代码回滚，必须单独确认。
