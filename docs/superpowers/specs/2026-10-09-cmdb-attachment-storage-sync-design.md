# Cmdb 附件存储目录与云同步设计

## 1. 目标

为 Netcatty 内置 Cmdb 提供每项目独立的附件存储目录，并打通工单附件的本地落盘、目录迁移、Netcatty S3 自动上传、异机按需下载和完整性校验。

本设计只处理工单附件。资产数据、人员数据和其他 Cmdb 业务数据继续使用现有加密快照同步链路。

## 2. 已确认决策

1. 附件目录按项目独立配置。
2. 用户通过 Netcatty 原生目录选择器选择目录，不手工输入路径。
3. 更换目录时，已有附件自动迁移；全部文件校验成功后才切换目录。
4. 附件元数据继续进入 Cmdb 加密同步快照。
5. 附件二进制文件不进入快照，复用 Netcatty 已配置的 S3 或兼容对象存储通道。
6. 本机上传后自动补传云端；异机只同步元数据，打开或下载附件时按需拉取。
7. S3 不可用时不影响本地附件使用，恢复连接后自动补传。

## 3. 当前问题与根因

### 3.1 目录无法选择

`integrations/netcatty/cmdb/ConfigCenter.jsx` 当前根据项目编号拼出只读展示路径，没有原生目录选择入口，也没有保存路径的项目字段。

`internal/store/work_order_attachments.go` 当前从数据库路径推导统一附件根目录，无法按项目解析用户配置。因此只增加前端按钮不能解决问题，必须补齐项目配置、后端解析和迁移链路。

### 3.2 附件未真正跨机器同步

附件元数据已经具备内容哈希、S3 对象键和同步状态，并进入 Cmdb 快照；附件二进制文件仍停留在本地磁盘。

仓库中的 `plugins/netcatty-cmdb/attachment_sync.js` 和 `docs/cmdb-attachment-s3-sync-plan.md` 属于未纳入正式集成链路的原型或计划，不能作为已实现功能。正式实现必须进入受版本控制的 Netcatty 集成源码和装配流程。

## 4. 数据模型

### 4.1 项目附件目录

在 `cmdb_projects` 增加：

- `attachment_root TEXT NOT NULL DEFAULT ''`

含义：

- 空值：使用系统默认目录。
- 非空值：使用用户为该项目选择的绝对目录。

默认目录仍由 Cmdb 服务根据数据库目录稳定推导，保证旧安装无需配置即可继续运行。

路径不进入跨机器业务快照。绝对路径属于本机设置，不能把机器 A 的 Windows 路径覆盖到机器 B。项目稳定标识和附件元数据同步，目录配置只保存在本机。

### 4.2 附件元数据

沿用现有字段：

- `content_hash`：SHA-256 内容哈希。
- `s3_key`：对象存储相对键。
- `s3_status`：`pending`、`synced` 或 `failed`。

附件元数据继续参与项目快照合并，二进制内容不进入 JSON 快照。

## 5. 本地目录解析

新增统一的项目附件目录解析入口，上传、下载、删除、本地存在性检查和迁移均通过该入口获取路径，禁止各接口自行拼接目录。

解析顺序：

1. 读取项目本机 `attachment_root`。
2. 非空时清理并验证绝对路径。
3. 为空时回退到默认附件根目录下的项目专属目录。
4. 附件实体继续按内容哈希分层存放，避免文件名冲突和重复内容重复占用。

## 6. 目录选择与迁移

### 6.1 原生目录选择

扩展 `integrations/netcatty/electron/cmdbBridge.cjs`，使用 Electron `dialog.showOpenDialog({ properties: ["openDirectory", "createDirectory"] })` 返回用户确认的目录。

通过 preload 暴露最小的 Cmdb 目录选择方法，前端不能直接访问任意文件系统 API。

### 6.2 迁移流程

目录切换由后端执行，流程如下：

1. 校验目标目录为绝对路径并可创建、可写。
2. 统计当前项目附件数量和总大小，返回迁移预览。
3. 用户确认后，在目标目录创建迁移临时区域。
4. 逐个复制当前项目的附件实体。
5. 对复制结果重新计算 SHA-256，并与元数据比对。
6. 全部成功后原子更新项目 `attachment_root`。
7. 新目录正式生效后保留旧目录副本，供用户确认后自行清理；本轮不自动删除旧文件。

任何文件复制或校验失败时：

- 不更新 `attachment_root`。
- 继续使用原目录。
- 返回失败文件和明确原因。
- 清理本次迁移产生的临时文件，不影响已有附件。

“恢复默认”使用同一迁移流程，目标改为系统默认项目目录。

## 7. 云同步架构

采用双轨同步：

1. **元数据轨道**：Cmdb 快照继续携带工单与附件元数据，使用 Netcatty 现有加密同步流程。
2. **二进制轨道**：附件实体通过 Netcatty 已启用的 S3 或兼容对象存储通道流式上传和下载。

对象键使用稳定的内容哈希，例如：

```text
attachments/<hash[0:2]>/<hash[2:4]>/<hash>.bin
```

同一内容在多个工单或多台机器上复用同一对象，不依赖原始文件名。

## 8. 上传与自动补传

上传流程：

1. 用户选择附件。
2. Cmdb 服务将文件写入当前项目实际目录并计算 SHA-256。
3. 保存附件元数据，初始状态为 `pending`。
4. 触发 Cmdb 元数据同步请求。
5. Netcatty S3 可用时，后台队列按对象键检查并上传文件。
6. 上传成功后回写 `synced`；失败时记录 `failed` 或保持可重试状态。

断网或 S3 未配置时，本地上传仍成功。补传任务在网络或同步状态恢复后重新处理未同步附件，不要求用户再次选择文件。

## 9. 异机按需下载

异机同步到附件元数据后：

1. 列表显示文件名、大小和云端状态。
2. 用户打开或下载附件时先检查本地内容哈希文件。
3. 本地不存在且 `s3_status` 表示已上传时，通过 Netcatty 宿主流式下载到临时文件。
4. 下载完成后计算 SHA-256。
5. 校验一致后原子移动到当前项目实际目录。
6. 校验失败时删除临时文件并显示真实错误。

不在项目同步时自动下载全部附件，避免无意义占用磁盘和网络。

## 10. 设置界面

附件存储区沿用 Netcatty 原生设置页组件和主题，展示：

- 当前项目。
- 当前实际目录。
- 目录状态。
- 本地附件数量与占用空间。
- 云同步状态及待补传数量。
- “选择目录”操作。
- “恢复默认”操作。

选择目录后先展示迁移确认信息：原目录、目标目录、文件数量和总大小。迁移期间显示进度并禁用重复操作。

附件状态使用明确文案：

- 本地可用。
- 等待上传。
- 同步中。
- 已同步。
- 同步失败。
- 仅云端。

## 11. 接口边界

后端需要提供最小接口集：

- 读取当前项目附件存储状态。
- 预检新目录和迁移规模。
- 执行目录迁移。
- 恢复默认目录。
- 查询待同步附件和本地文件状态。
- 更新附件 S3 状态。
- 将云端下载完成的临时文件导入本地 CAS。

Electron 桥接需要提供：

- 原生目录选择。
- 查询 Netcatty S3 可用状态。
- 流式上传本地附件。
- 流式下载对象到指定的受控临时路径。

所有路径必须由主进程或后端校验，渲染进程不能提交任意路径执行读写。

## 12. 错误处理与可回滚边界

- 目录不可写：拒绝保存，不切换路径。
- 迁移失败：继续使用旧目录，返回失败清单。
- 上传失败：保留本地文件和待重试状态。
- 下载失败：不生成正式本地文件。
- 哈希不一致：删除临时文件，标记错误并允许重试。
- S3 未启用：明确显示“仅本地”，不伪造已同步。
- 快照只同步元数据：避免大文件导致 Netcatty 同步载荷膨胀或内存压力。

本轮不自动删除迁移前的旧目录文件，以此作为可回滚边界。

## 13. 测试设计

### 13.1 Go 存储与接口测试

- 项目目录保存、读取和默认回退。
- 不同项目目录互不影响。
- 不可写目录拒绝。
- 迁移预检统计正确。
- 迁移成功后附件可下载。
- 迁移中任一文件失败时项目仍使用旧目录。
- 迁移后每个文件 SHA-256 一致。
- 恢复默认目录复用迁移逻辑。
- 附件元数据进入快照，绝对目录不进入快照。

### 13.2 Electron 桥接测试

- 取消目录选择不修改配置。
- 返回用户确认的目录。
- S3 未配置时返回明确状态。
- 上传和下载只允许受控附件对象键及路径。
- 流式传输失败时错误向上返回。

### 13.3 前端测试

- 设置页显示真实目录和状态。
- 选择目录后展示迁移确认。
- 迁移成功刷新状态。
- 迁移失败保持原路径并展示原因。
- 附件显示本地与云端状态。
- 仅云端附件触发按需下载。

### 13.4 集成与手工验收

1. 运行 `go test ./...`。
2. 运行 Cmdb 原生组件和 Electron 桥接测试。
3. 运行 Netcatty 装配脚本测试、lint 和生产构建。
4. 在隔离测试库中选择自定义目录，上传附件并确认实际落盘。
5. 重启 Netcatty，确认目录设置和附件仍可用。
6. 模拟 S3 断网上传，恢复后确认自动补传。
7. 模拟机器 A 上传、机器 B 同步元数据并按需下载，核对文件名、大小和 SHA-256。
8. 验证迁移失败时仍可从旧目录下载原附件。

不得使用正式数据库或正式端口完成上述测试。

## 15. 明确不做

- 不把附件二进制塞入 Cmdb 或 Netcatty JSON 快照。
- 不新增独立附件服务器。
- 不要求用户在 Cmdb 重复填写 S3 密钥。
- 不自动下载全部云端附件。
- 不自动删除目录迁移前的旧文件。
- 不修改与附件存储和同步无关的资产、组织、IPAM 或工单业务结构。
