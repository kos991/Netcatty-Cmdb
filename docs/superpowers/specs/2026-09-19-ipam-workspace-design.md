# Netcatty Cmdb IPAM/IP 工作区设计

## 1. 文档状态

- 状态：业务规则和原生界面原型已由用户确认，采用 A“12 列紧凑网格”方案，进入实施计划阶段。
- 日期：2026-09-19。
- 适用范围：Netcatty 原生 Cmdb 的 IP 地址、网段、VLAN、VXLAN、占用关系、分配释放和数据交换。
- 原型：`.superpowers/brainstorm/203-1789721277/content/ipam-workspace-v1.html`。
- 前置设计：`docs/superpowers/specs/2026-09-18-unified-asset-workspace-design.md`。

## 2. 目标

1. 在同一项目内统一管理 IP 地址、网段、VLAN 和 VXLAN。
2. 一眼区分设备占用、应用占用、设备与应用共同占用、空闲、保留和冲突。
3. IP 地址与统一设备资产、业务系统、网络接口、VLAN 和 VXLAN 建立真实双向关系，不通过备注或关键词假关联。
4. 从 IPAM 分配或释放地址时同步更新关联对象；任一步失败时整笔事务回滚。
5. 保持紧凑、安静的 Netcatty 原生工具界面，不恢复浏览器版，不引入 Ant Design 或 MUI。
6. 所有数据按项目隔离并纳入现有同步元数据和云同步路径。

## 3. 非目标

- 不实现自动扫描、Ping 探测、SNMP 发现、DHCP 或 DNS 管理。
- 不实现拓扑图、关系图或复杂网络自动编排。
- 不根据名称、备注或颜色推断占用来源。
- 不要求新增资产时一次录完 IPAM、VLAN、VXLAN 和端口链路。
- 不在地址网格中重复显示完整 IP、对象名称、图标或说明文字。
- 不物理删除仍有关联关系的 IP、网段、VLAN 或 VXLAN。

## 4. 统一术语与状态模型

### 4.1 地址状态

每个 IP 地址只返回一个最终展示状态：

| 状态 | 判断规则 | 网格表现 |
| --- | --- | --- |
| `free` | 没有设备或应用关系，且未被保留 | 中性背景，仅显示主机位数字 |
| `reserved` | 网关、系统预留或管理员保留 | 中性背景、虚线边框 |
| `device` | 只有一个设备资源关系 | 克制的蓝色 |
| `application` | 只有应用关系 | 克制的紫色 |
| `mixed` | 同一地址同时有关联设备和应用 | 克制的金色 |
| `conflict` | 存在两个不允许共存的设备占用，或关系数据互相矛盾 | 红色 |

多个业务系统共享同一服务地址是合法场景，不因此标记冲突。设备与其承载应用共用地址时显示 `mixed`，不重复计入设备占用和应用占用。

### 4.2 汇总口径

- 总占用数：`device + application + mixed + conflict` 的唯一 IP 数量。
- 设备占用数：只统计 `device`。
- 应用占用数：只统计 `application`。
- 共同占用数：只统计 `mixed`。
- 空闲数：只统计 `free`。
- 异常 / 保留数：`conflict + reserved`。
- 使用率：总占用数 / 网段可用地址总数。

所有汇总基于完整筛选结果，不受当前页限制。

## 5. 数据关系

### 5.1 IP 地址空间

- `ip_subnets` 保存网段定义、网络类型、CIDR、网关及默认 VLAN/VXLAN。
- `ip_pool` 保存已物化的地址记录、保留状态和备注。
- 已定义 CIDR 但尚未写入 `ip_pool` 的地址在查询时生成只读空闲记录；首次分配时再物化，避免为大网段预写大量空行。
- `/24` 网段展示 `.1` 至 `.254`；`.0` 网络地址和 `.255` 广播地址不进入可分配网格。

### 5.2 设备占用

- 设备占用以 `cmdb_asset_interfaces.ip_pool_id` 为明确关系。
- 网络接口保留 IP 用途，例如设备 IP、管理 IP、终端物理 IP、虚拟桌面 IP 和业务 IP。
- 云桌面终端可以同时拥有终端物理 IP 和虚拟桌面 IP，两条关系独立。
- 历史 `assets.ip`、`assets.terminal_ip`、`servers.mgmt_ip` 和 `servers.biz_ip` 在兼容期通过精确 IP 匹配只读展示；新写入统一走网络接口关系。

### 5.3 应用占用

- 业务系统使用独立的应用访问端点记录，至少包含业务系统、IP、用途、协议、端口和可选承载设备。
- 一个业务系统可以有多个访问端点；多个业务系统可以合法共享同一 IP。
- 应用端点可引用承载设备，但承载关系不等于地址占用关系，必须明确选择 IP。

### 5.4 共同占用与冲突

- 一个 IP 同时被设备接口和应用访问端点引用时显示共同占用。
- 多个应用共享地址仍是应用占用；同时存在设备接口时为共同占用。
- 两个不同设备资源的接口引用同一 IP 时默认判定冲突，除非以后新增明确的共享地址类型；本轮不增加该例外。
- 冲突只读展示所有来源，处理时必须逐项解除关系，不能一键清空全部对象。

## 6. 原生界面

### 6.1 页面结构

```text
┌ 网段与地址空间 ─┬ IPAM/IP 搜索、导入、导出、新增网段 ┐
│ 专网             │ IP 地址 | VLAN | VXLAN              │
│ 内网             │ 网段摘要与占用统计                  │
│ 外网             │ 状态筛选与网络类型筛选              │
│                  │ 12 列 IP 数字网格        │ 地址详情 │
└──────────────────┴──────────────────────────┴──────────┘
```

- 左侧按专网、内网、外网分组展示网段，显示 CIDR、VLAN 和使用率。
- 顶部搜索覆盖完整 IP、主机位、设备、业务系统、人员、组织、VLAN 和 VNI。
- `IP 地址 / VLAN / VXLAN` 使用分段控件切换，不新增多级路由。
- 右侧详情抽屉不遮挡网段侧栏和主要操作区。

### 6.2 A“12 列紧凑网格”

- 默认每页 96 个地址，在常见桌面宽度显示约 12 列。
- 地址块高度约 36px、圆角不超过 4px，只显示主机位数字，例如 `10.20.30.12` 显示为 `12`。
- 完整 CIDR 始终显示在网格上方；悬停提示和详情抽屉显示完整 IP。
- 地址块内不显示图标、对象名称、状态文字或第二行说明。
- 空闲和保留使用中性色；只有设备占用、应用占用、共同占用和冲突使用状态色。
- 设备占用蓝色、应用占用紫色、共同占用金色、冲突红色。
- 选中地址只增加单层主题轮廓，不再叠加另一套背景或阴影。
- 顶部图例使用小色块和文字，不使用图标。

### 6.3 地址详情

地址详情显示：

- 完整 IP、网段、网络类型、网关、VLAN 和 VXLAN。
- 最终状态及状态计算依据。
- 全部关联设备接口，包括设备名称、资产编码、接口、IP 用途、人员和组织。
- 全部关联业务系统，包括系统名称、端点用途、协议、端口、负责人和承载设备。
- 可进入统一设备资产或业务系统档案。
- 空闲地址显示分配入口；占用地址按关系逐项解除。

## 7. 操作流程

### 7.1 新增网段

管理员填写网段名称、网络类型、CIDR、网关、默认 VLAN、默认 VXLAN 和备注。保存后立即生成逻辑地址空间；网关自动标记保留，不要求逐条录入地址。

CIDR 必须是合法 IPv4 前缀且至少存在两个可用主机地址。同项目内网段不能重名，地址范围不能重叠。

### 7.2 分配给设备

1. 点击空闲地址。
2. 选择“设备资源”。
3. 选择设备、已有接口或“自动创建默认接口”、IP 用途及可选 VLAN/VXLAN。
4. 后端校验项目、地址状态、设备和网络配置。
5. 同一事务物化 `ip_pool` 地址并写入设备接口关系。
6. 成功后刷新 IPAM 和设备档案；失败时不留下半条关系。

### 7.3 分配给应用

1. 点击空闲地址或已有设备占用地址。
2. 选择“业务系统”。
3. 选择业务系统、用途、协议、端口和可选承载设备。
4. 后端写入应用访问端点。
5. 空闲地址变为应用占用；设备占用地址变为共同占用。

### 7.4 释放与解除关系

- 地址详情按设备接口或应用端点逐项解除。
- 共同占用地址解除应用后仍保留设备占用，解除设备后仍保留应用占用。
- 最后一条关系解除后，地址回到空闲；保留地址仍保持保留。
- 兼容 `/release` 接口只能用于确认只有一条关系的地址；多关系地址返回明确错误。

## 8. VLAN 与 VXLAN

- VLAN 至少包含 VLAN ID、名称、网络类型、用途、关联网段和状态。
- VXLAN 至少包含 VNI、名称、用途、可选关联 VLAN 和状态。
- VLAN ID 合法范围为 1-4094；VNI 合法范围为 1-16777215。
- 网段可设置默认 VLAN 和默认 VXLAN；分配地址时自动带出，但管理员可以在合法范围内修改。
- 删除被网段、设备接口、应用端点或链路引用的 VLAN/VXLAN 时必须阻止并返回引用数量。
- VLAN 和 VXLAN 各自支持搜索、分页、新增、编辑、停用、导入和导出。

## 9. API 约定

保留现有接口并扩展响应：

```text
GET    /api/ip_pool/summary
GET    /api/ip_pool/visualization
GET    /api/ip_pool
GET    /api/ip_pool/{id}/relations
POST   /api/ip_pool/{id}/allocate
POST   /api/ip_pool/{id}/release
DELETE /api/ip_pool/{id}/relations/{relation_type}/{relation_id}
GET    /api/ip_subnets
POST   /api/ip_subnets
PUT    /api/ip_subnets/{id}
DELETE /api/ip_subnets/{id}
GET/POST/PUT/DELETE /api/cmdb/vlans
GET/POST/PUT/DELETE /api/cmdb/vxlans
```

`visualization` 和列表条目新增：

```json
{
  "host_number": 12,
  "display_state": "mixed",
  "device_count": 1,
  "application_count": 2,
  "conflict_reason": ""
}
```

详情接口返回明确的设备和应用关系数组。接口不接受前端传入的状态计算结果，最终状态始终由后端关系数据计算。

## 10. 导入导出

- 导出使用当前网段、状态、占用来源和关键词筛选，导出全部匹配记录，不受当前页限制。
- 地址导出包含完整 IP、网段、展示状态、设备占用对象、应用占用对象、VLAN、VXLAN 和备注。
- 网段、VLAN、VXLAN 使用独立工作表，避免把网络配置混入资产首次导入模板。
- 导入必须先预览并校验 CIDR、地址范围、重复 IP、VLAN/VNI、跨项目引用和冲突关系。
- 确认导入在单一事务中提交；任一行失败整批回滚。
- 首次启动和正式发布包不写入演示 IP、网段、VLAN 或 VXLAN 数据。

## 11. 错误与兼容处理

- 地址、网段、设备、应用、VLAN 和 VXLAN 必须属于同一项目。
- 地址冲突必须返回具体对象，不返回笼统的“操作失败”。
- 关系写入失败不得用修改 `ip_pool.status` 伪造成功。
- 历史文本状态继续兼容读取；新界面以关系计算结果为准。
- 历史资产 IP 通过精确字段匹配展示，不按名称或备注猜测应用占用。
- 旧接口继续可用一个稳定发布周期；新界面不再直接写自由文本人员、部门和房间作为占用来源。

## 12. 测试策略

### 12.1 后端

- CIDR 可用地址范围、主机位和网关保留。
- 设备占用、应用占用、共同占用、空闲、保留和冲突六种状态。
- 多应用共享地址不冲突，两个不同设备占用同一地址判冲突。
- 汇总口径不重复计数且不受分页影响。
- 设备和应用分配、逐项解除及失败整体回滚。
- VLAN/VXLAN 合法范围、默认带出、引用保护和项目隔离。
- 历史资产精确 IP 匹配和旧接口兼容。
- 导入预览、事务提交、重复关系、冲突数据和全量筛选导出。

### 12.2 原生界面

- A 方案默认 12 列、36px 高、只显示主机位数字且不出现地址图标。
- 空闲和保留使用中性色，只有占用与冲突使用状态色。
- 搜索、状态筛选、占用来源筛选、分页和网段切换正确。
- 详情同时展示设备与应用关系并可穿透档案。
- 共同占用逐项解除后状态正确降级。
- 地址分配目标可在设备和应用之间切换并联动字段。
- VLAN/VXLAN 视图、导入导出、错误、空状态、深浅主题和窄窗口无遮挡。

## 13. 验收标准

| 编号 | 合格标准 |
| --- | --- |
| AC-01 | 网格默认采用 A 方案：约 12 列、36px 高、只显示主机位数字。 |
| AC-02 | 网格不显示图标、对象名称或第二行说明。 |
| AC-03 | 空闲和保留保持中性，设备、应用、共同占用和冲突使用不同状态色。 |

## 14. 回滚边界

- 新增表和同步元数据不通过回滚删除，避免丢失已经建立的设备和应用关系。
- 新 IPAM 界面可以回退现有列表 / 网格页面；后端新增字段保持向后兼容。
- VLAN/VXLAN 子视图可以独立关闭，不影响 IP 地址查询与原有分配接口。
- 应用端点功能可以独立关闭，设备 IPAM 关系继续可用。
- 旧文本占用字段保留一个稳定发布周期，确认迁移完成后再评估只读或清理。
