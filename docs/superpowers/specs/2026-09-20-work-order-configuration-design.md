# Netcatty Cmdb 工单与配置中心设计

## 1. 文档状态

- 日期：2026-09-20。
- 状态：工单页面方向已确认，等待配置中心原型验收。
- 适用范围：Netcatty 原生 Cmdb 的新建工单、工单统计及配置中心中的工单配置。
- 当前工单原型：`.superpowers/brainstorm/11-1789779172/content/work-order-stats-filters-v13.html`。
- 本文不授权直接修改正式业务代码或发布版本；配置中心原型确认后再生成正式实施计划。

## 2. 已确认目标

1. 工单管理默认进入直接可填写的“新建工单”页面，不使用弹窗，不展示工单记录列表。
2. 右上角紧凑下拉只切换“新建工单”和“工单统计”。
3. 工单编号不允许手工填写，由当前项目的配置规则在创建工单时自动生成。
4. 工单类别、运维类型和优先级由配置中心维护，页面不再写死选项。
5. 不同工单类别使用对应表单模板，但必须保持简单，不建设审批流、派单、SLA 或复杂流程引擎。
6. 当前项目从 Cmdb 项目上下文读取；工单、配置、关联资产、统计和导出均按项目隔离。
7. 关联资产支持搜索当前项目内的名称、编码、SN 和 IP，支持多选或不选。
8. 工单统计支持多维组合筛选，并按全部匹配记录导出 XLSX，不受页面显示范围限制。

## 3. 当前实现事实与缺口

- 后端已经通过 `ProjectScope` 和 `X-Cmdb-Project` 设计了项目隔离，工单不能关联其他项目资产。
- 当前工单创建逻辑在未收到编号时写死生成 `WO + YYYYMMDD + 数据库 ID`，尚无可配置规则。
- 当前原生工单页面仍使用固定的业务类型、状态、结果和优先级数组，且使用弹窗表单，与已确认原型不同。
- 当前配置中心只有设备类型、软件目录、位置、状态、厂商型号、凭证、编码标签，没有工单配置。
- 当前 `CmdbWorkspace` 只取项目列表第一项显示名称；Electron 请求通道也没有传入当前项目请求头。正式实现前必须补齐“当前项目选择 -> 请求作用域”的链路，不能把列表第一项继续解释为用户选择的当前项目。

## 4. 字段来源与配置边界

| 表单字段 | 数据来源 | 配置中心能力 | 说明 |
| --- | --- | --- | --- |
| 工单编号 | 工单编号规则 | 可配置 | 表单只读，创建时由后端生成，创建后不可修改。 |
| 当前项目 | Netcatty Cmdb 当前项目 | 项目设置维护名称和编码 | 不在工单表单切换项目。 |
| 工单类别 | 工单类别目录 | 新增、编辑、排序、停用、模板配置 | 已被引用的类别不得物理删除。 |
| 优先级 | 优先级目录 | 名称、排序、显示级别、默认项、停用 | 已停用项保留历史显示。 |
| 发生/维护/变更/调配时间 | 类别表单模板 | 字段名称、是否必填、默认当前时间、排序 | 最终值属于每张工单。 |
| 运维类型 | 运维类型目录 | 新增、编辑、排序、停用 | 筛选和统计使用同一目录。 |
| 经办人 | 当前项目组织架构人员 | 不重复配置人员 | 记忆当前项目中上次选择。 |
| 工时（分钟） | 工单业务数据 | 模板可设置默认值与是否必填 | 单位固定为分钟。 |
| 工单主题 | 工单核心字段 | 不可删除，模板可设置是否必填 | 默认必填。 |
| 类别专属内容 | 类别表单模板 | 可添加、编辑、排序、停用 | 支持有限字段类型，不建设通用低代码平台。 |
| 关联资产 | 当前项目资产数据 | 不单独配置 | 搜索范围跟随当前项目与现有资产分类。 |
| 附件 | 工单附件 | 项目设置维护存储路径 | 固定支持多附件，单文件上限 20MB；工单表单不配置路径。 |

### 4.1 不进入配置中心的内容

- 经办人由组织架构提供，不能在工单配置中再维护一份人员名单。
- 关联资产由当前项目资产台账提供，不能维护重复资产目录。
- 当前项目由 Cmdb 项目上下文决定，工单表单不提供自由文本或项目下拉。
- 工单主题、工时、附件内容和处理说明属于具体工单，不是配置项；附件存储根目录属于项目设置。
- 统计筛选条件属于查询状态，不进入配置中心；后续可在统计页增加“保存筛选方案”，但不列入本阶段。

## 5. 工单编号规则

### 5.1 配置项

每个项目只有一条启用中的工单编号规则：

| 配置项 | 可选值或限制 | 默认值 |
| --- | --- | --- |
| 固定前缀 | 1-12 位大写字母或数字 | `GD` |
| 分隔符 | 无、`-`、`_` | `-` |
| 日期段 | 无、`YYYY`、`YYYYMM`、`YYYYMMDD` | `YYYYMMDD` |
| 流水号位数 | 3-8 位 | 4 位 |
| 重置周期 | 不重置、每年、每月、每日 | 每日 |

配置界面实时显示示例，例如：`GD-20260920-0001`。界面采用受控选项拼装规则，不允许直接录入任意模板表达式，避免产生无法解析或不能保证唯一的格式。

### 5.2 生成规则

- 工单创建请求不接受客户端传入的 `order_no`；后端始终按当前项目规则生成。
- 流水号以“项目 + 规则版本 + 当前周期”为作用域递增。
- 编号生成与工单写入必须在同一事务中完成，并由唯一索引保证并发下不重复。
- 修改规则只影响修改后创建的工单，不重写历史编号。
- 工单编号创建后不可编辑；复制工单时重新生成编号。
- 规则停用或损坏时拒绝创建工单并明确提示配置问题，不能回退为随机编号或空编号。

## 6. 工单配置模型

### 6.1 工单类别

默认提供：

- 故障处理。
- 日常维护。
- 变更操作。
- 资产调配。

每项包含名称、排序、启用状态、默认优先级、默认运维类型和关联表单模板。允许新增和编辑；已使用类别只能停用，不能物理删除。

### 6.2 运维类型

默认提供：排障、优化、响应、值守。每项包含名称、排序和启用状态。已使用项只能停用；停用后不再出现在新建工单中，但历史统计和筛选仍可显示。

### 6.3 优先级

默认提供：P1（紧急）、P2（较高）、P3（普通）、P4（较低）。每项包含名称、排序、语义级别和启用状态，其中一个启用项可设为默认值。颜色只作为辅助，不作为唯一识别方式。

### 6.4 类别表单模板

核心字段固定存在：工单编号、当前项目、工单类别、运维类型、经办人、工时、主题、关联资产和附件。配置中心不能删除这些字段。

类别专属字段支持：

- 单行文本。
- 多行文本。
- 日期时间。
- 数字。
- 单选下拉。

每个字段可设置名称、字段类型、是否必填、默认值、排序和启用状态；单选下拉还可维护选项。字段键由系统生成并保持稳定，重命名标签不能破坏历史数据。已经产生数据的字段只能停用，不能物理删除或改变字段类型。

## 7. 配置中心信息架构

为避免顶部堆积十多个选项，配置中心分为三个一级分组：

1. **资产配置**：设备类型、软件目录、位置目录、设备状态、厂商与型号、凭证中心、编码与标签。
2. **工单配置**：编号规则、工单类别、运维类型、优先级。
3. **项目设置**：当前项目名称、项目编码、附件存储路径及项目信息；项目切换仍放在 Cmdb 全局项目入口，不放进工单表单。

一级分组使用紧凑的顶部切换，不做永久左右分栏。工单配置内部使用次级页签，表格管理目录项，编辑操作使用右侧抽屉；编号规则使用单页设置表单。

附件存储按项目独立设置，默认位于 Netcatty 用户数据目录下的 `cmdb/attachments/<项目编码>`。管理员可以选择新目录或直接打开当前目录；更换目录时必须迁移现有附件并校验完整性，失败则保持原路径。云同步保存附件内容和元数据，不同步本机绝对路径。

### 7.1 工单类别编辑抽屉

抽屉分为两段：

- 基本设置：名称、排序、默认优先级、默认运维类型、启用状态。
- 表单模板：固定核心字段摘要和类别专属字段列表。

类别专属字段可以新增、编辑、排序和停用。抽屉底部提供“预览表单”，直接按当前未保存配置展示新建工单片段，避免保存后再反复切页验证。

## 8. 新建工单联动

1. 进入页面时加载当前项目、编号规则摘要、启用中的工单类别、运维类型、优先级和类别模板。
2. 工单编号显示“保存后按规则生成”，旁边显示当前规则示例，不提供输入框。
3. 当前项目显示项目名称和项目编码，不允许在表单中修改。
4. 切换工单类别后，自动应用该类别的默认优先级、默认运维类型和专属字段。
5. 经办人读取当前项目组织架构；首次选择后按当前项目记忆，下次自动带入。
6. 关联资产抽屉只搜索当前项目资产；跨项目资产即使构造请求也由后端拒绝。
7. 创建成功后显示生成的工单编号，再清空表单继续开单；经办人记忆保留。

## 9. 工单统计与导出

统计页保留以下多维条件：

- 时间范围、开始日期、结束日期。
- 关键词。
- 工单类别、运维类型、经办人、设备或对象类型。
- 优先级、资产关联状态、指定资产、部门。
- 最小工时、最大工时、附件状态。

统计维度可切换为工单类别、运维类型、经办人、设备或对象类型、关联资产、日期和优先级。筛选选项必须读取当前项目配置；已停用但仍被历史工单引用的值在历史筛选中继续可选。

导出规则：

- 导出当前项目下符合全部当前筛选条件的记录，不受页面分页限制。
- 格式为 XLSX。
- 工作簿包含“统计汇总”和“工单明细”两个工作表。
- 文件名包含项目编码与导出时间。
- 导出失败必须显示后端返回的真实错误，不生成空文件伪装成功。

## 10. 数据与接口方向

正式实现预计新增以下项目级数据：

- 工单编号规则及规则版本。
- 工单流水号计数器。
- 工单类别目录。
- 运维类型目录。
- 优先级目录。
- 工单类别字段模板与下拉选项。
- 工单动态字段值。
- 工单与多个资产的关联表。
- 工单附件元数据及本地文件引用。

所有表必须包含 `project_id` 和同步所需稳定标识；配置、编号流水和工单数据使用同一项目边界。API 延续现有 JSON、分页和明确错误返回风格。

## 11. 配置变更与历史兼容

- 配置项被历史工单引用后不得物理删除，只能停用。
- 配置项重命名不重写历史工单快照；历史详情应保留创建时名称，同时可关联当前配置项。
- 模板字段停用后，新建表单不显示，历史详情和导出继续显示已有值。
- 编号规则变更不影响历史编号，也不重新开始旧规则的计数器。
- 首次升级时把现有固定选项迁移为默认配置，不写入示例工单。

## 12. 配置中心原型范围

下一版原型必须展示并可操作：

1. 配置中心三个一级分组及工单配置四个次级页签。
2. 编号规则设置、实时预览和保存反馈。
3. 工单类别列表及新增/编辑抽屉。
4. 类别默认优先级、默认运维类型和表单模板编辑。
5. 运维类型、优先级的新增、编辑、排序、停用与引用保护提示。
6. 从配置中心打开工单表单预览，验证字段联动。
7. 新建工单中的编号只读和当前项目来源说明。

原型只验证信息架构与交互，不修改正式数据库，不进入发布包。

## 13. 验收标准

| 编号 | 合格标准 |
| --- | --- |
| AC-01 | 工单编号不可手填，必须由当前项目的启用规则自动生成。 |
| AC-02 | 编号规则支持前缀、分隔符、日期段、流水号位数和重置周期，并实时预览。 |
| AC-03 | 编号生成并发安全，项目内唯一，规则变化不改写历史编号。 |
| AC-04 | 当前项目来自 Cmdb 项目上下文，不使用自由文本，也不固定读取项目列表第一项。 |
| AC-05 | 工单类别、运维类型和优先级均可新增、编辑、排序、停用，并具备引用保护。 |
| AC-06 | 不同工单类别可配置默认值和类别专属字段模板。 |
| AC-07 | 经办人复用组织架构人员，关联资产复用当前项目资产，不建立重复配置目录。 |
| AC-08 | 新建工单保持单页表单、资产抽屉、多附件和创建后继续开单。 |
| AC-09 | 统计支持既定多维筛选，筛选选项与配置中心联动。 |
| AC-10 | XLSX 导出覆盖全部匹配记录，并包含统计汇总和工单明细。 |
| AC-11 | 配置中心保持 Netcatty 原生组件、紧凑密度和非永久左右分栏布局。 |
| AC-12 | 原型文件只位于 `.superpowers/`，不进入正式发布包。 |
| AC-13 | 项目设置显示附件管理路径，并支持选择目录、打开目录及查看附件数量和空间占用。 |

## 14. 非目标

- 不实现审批、派单、SLA、待办、多人协作流程或人员信息面板。
- 不实现任意脚本表达式编号模板。
- 不实现完整低代码表单设计器、跨字段计算或条件分支。
- 不在本阶段增加工单记录列表。
- 不允许工单跨项目关联资产或配置。

## 15. 回滚边界

- 正式实现时新增的配置表和规则版本只做增量迁移，不删除现有工单列。
- 新工单页面可单独回退旧页面，已生成的编号和配置数据保持可读。
- 配置中心工单分组可独立隐藏，资产配置继续可用。
- 项目上下文链路属于所有 Cmdb 模块共同依赖，不能通过回退到“始终取第一项目”规避问题。
