# Netcatty Cmdb 组织架构工作区设计

## 1. 文档状态

- 状态：业务规则和原生界面原型已由用户确认，进入实施计划阶段。
- 日期：2026-09-18。
- 适用范围：Netcatty 原生 Cmdb 的组织树、人员档案、人员调动、资源归属和组织人员数据交换。
- 原型：`.superpowers/brainstorm/203-1789721277/content/organization-workspace-v1.html`。

## 2. 目标

1. 使用符合机关单位实际情况的任意层级组织树，不再固定为“组织、部门、分组”三级。
2. 一个项目只允许一个根机关单位，全部正式机构均位于该根节点下。
3. 组织节点类型可自定义，办事处、派出机构、科室等不受固定层级限制。
4. 每个人员只能有一个正式归属节点，不支持多个正式部门，也不引入工作组。
5. 管理员可以把单个人员或选中人员拖到目标组织节点完成调动。
6. 调动时必须由管理员决定人员名下资源是否跟随，不建立申请和审批流。
7. 组织、人员、资产归属、导入导出和云同步继续按项目隔离。

## 3. 非目标

- 不实现工作组、项目组、兼职组织、多部门任职或矩阵式组织。
- 不支持通过拖拽移动组织节点；组织节点移动必须使用明确的新上级选择弹窗。
- 不实现人员调动申请、审批、待办或会签流程。
- 不物理删除已有组织、人员及历史关系。
- 不在正式界面继续使用自由文本维护组织、部门或分组。

## 4. 组织模型

### 4.1 根机关单位

- 每个项目只能有一个根节点。
- 根节点代表当前项目管理的机关单位。
- 根节点不能删除、移动或停用，只能修改名称和节点类型。
- 首次进入且项目没有根节点时，引导管理员创建根机关单位，不写入演示单位名称。

### 4.2 任意层级

组织树采用统一节点结构，节点通过 `parent_id` 形成任意深度层级，例如：

```text
机关单位
├── 内设机构
│   └── 科室
├── 派出机构
│   └── 办事处
│       └── 服务科
└── 直属单位
```

节点类型只表达业务含义、显示名称和图标，不限制父子层级。管理员可以根据实际机关设置，把办事处、部门、科室或自定义机构放在合理位置。

### 4.3 节点类型

系统默认提供：

- 机关单位。
- 内设机构。
- 部门。
- 科室。
- 派出机构。
- 办事处。
- 其他。

管理员可新增、重命名、排序和停用节点类型。被组织节点引用的类型不得物理删除；停用后历史节点继续显示，但新增或编辑节点不能再选择该类型。

### 4.4 节点生命周期

节点操作位于节点右侧菜单：

- 新增下级。
- 编辑节点。
- 移动节点。
- 停用节点。

移动节点时选择新上级并显示完整路径。后端必须阻止把节点移动到自身或其后代下面。存在人员、资产或启用中子节点时不得删除；本轮统一使用停用归档，不提供组织节点物理删除。

停用节点及其历史数据继续可查，但不能接收新人员、资产或下级节点。停用包含启用中子节点的节点前，必须先处理或停用子节点。

### 4.5 未归属

“未归属”是查询时生成的虚拟节点：

- 展示尚未匹配正式组织节点的历史人员和资源。
- 不写入组织表。
- 不能作为新增人员或资产的主动归属。
- 可把未归属人员拖到正式节点完成补录。

## 5. 人员模型

### 5.1 人员字段

- 人员编号：项目内唯一、必填，可手工填写或自动生成，默认格式 `RY-000001`。
- 姓名：必填。
- 主要归属节点：唯一且必填，必须是当前项目启用中的正式节点。
- 职务 / 岗位：可选的文本字段。
- 联系电话：可选。
- 人员状态：必填，来自项目内状态目录。
- 备注：可选。

正式界面、列表、详情和导入导出不再使用邮箱。数据库已有邮箱列保留兼容，不在本轮删除。

### 5.2 唯一归属

- 一个人只能属于一个正式组织节点。
- 不存在工作组或多组织成员关系。
- 组织路径根据节点 ID 实时计算，不把路径文本作为关系主键。
- 节点重命名或移动后，人员路径自动更新，不逐行重写人员文本字段。

### 5.3 人员状态

默认状态为：在岗、借调、挂职、退休、离职、停用。

状态目录可配置：

- 状态名称。
- 排序。
- 是否允许分配新资产。
- 是否表示人员已离岗。
- 启用或停用。

被人员引用的状态不能删除，只能停用。标记为已离岗的人员不能成为新资产责任人；变更为已离岗状态时必须先处理名下资源，或者在同一操作中完成交接。

## 6. 人员拖拽调动

### 6.1 操作方式

- 人员列表行提供明确拖拽手柄。
- 可直接拖动单个人员。
- 勾选多个人员后，拖动其中任意已选人员表示批量调动。
- 拖拽经过可接收节点时高亮目标。
- 停用节点、虚拟“未归属”节点、其他项目节点不能成为放置目标。
- 只有具备组织管理权限的管理员可以执行拖拽。

组织节点本身不支持拖拽，避免误移动整棵子树。

### 6.2 资源跟随确认

人员放置到目标节点后打开确认窗口，不建立二次审批。窗口展示：

- 原归属和目标归属完整路径。
- 将要调动的人员数量。
- 关联设备资源、业务系统、软件许可及其他责任资源。
- 每类资源的名称、编码、当前归属和数量。

管理员必须选择以下一种方式：

1. 资源全部跟随。
2. 资源全部保留原归属。
3. 逐项选择跟随资源。

确认前不写入任何数据。确认后，人员归属与选定资源归属在同一数据库事务中更新；任一写入失败则整体回滚。

### 6.3 履历

成功调动后分别记录：

- 人员调动履历：原节点、目标节点、操作人、时间和备注。
- 资源归属变更履历：资源引用、原节点、目标节点、关联人员和操作人。

资源选择“保留原归属”时只写人员调动履历，不伪造资源变更记录。

## 7. 资产归属联动

- 资产同时保留责任人和归属组织节点。
- 选择责任人时默认带出其主要归属，但管理员可在有权限时明确改为其他正式节点。
- 公共设备、服务器和业务系统允许只有组织归属，没有具体责任人。
- 资产交接给其他人员时，默认建议使用接收人的主要归属；保存前明确展示归属变化。
- 已离岗或状态不允许分配资产的人员不出现在责任人选择器中，但历史详情继续显示。
- 组织节点停用前必须列出人员和资源引用数量，并阻止新增关联。

## 8. 原生界面

### 8.1 页面结构

```text
┌ 组织树 ─────────┬ 人员搜索、筛选、导入导出、新增人员 ┐
│ 根机关单位       │ 人员分页表格                         │
│ ├ 内设机构       │ 姓名 / 编号 / 主要归属 / 岗位       │
│ ├ 办事处         │ 电话 / 资源数 / 状态 / 操作          │
│ └ 未归属         │                                      │
└─────────────────┴──────────────────────────────────────┘
```

- 左侧组织树显示节点类型图标、名称和包含下级的人员数量。
- 点击节点后，右侧显示该节点及全部后代人员。
- 人员列表保持分页；搜索覆盖姓名、人员编号、职务和电话。
- 顶部保留人员导入、导出和新增人员。
- 节点类型管理放在组织架构页内，不在配置中心重复入口。
- 使用 Netcatty 原生组件、Tailwind、Radix UI 和 Lucide 图标，不引入 Ant Design 或 MUI。

### 8.2 人员详情

人员详情抽屉显示：

- 基础信息和完整组织路径。
- 名下设备资源、业务系统和软件许可。
- 人员调动履历。
- 资源批量交接入口。

关联资源可继续打开统一资产档案。

## 9. 导入导出

### 9.1 组织模板

字段为：节点名称、节点类型、完整上级路径、排序、状态。

- 完整路径必须精确匹配，不按同名节点模糊推断。
- 导入先预览路径不存在、类型停用、同级重名和根节点冲突。
- 提交时在一个事务中按父级顺序写入。

### 9.2 人员模板

字段为：人员编号、姓名、主要归属完整路径、职务 / 岗位、联系电话、人员状态、备注。

- 不包含邮箱和工作组。
- 人员编号为空时可在预览阶段生成；一旦生成，提交必须沿用预览结果。
- 人员编号冲突时不得只按姓名覆盖。
- 主要归属路径和人员状态必须精确匹配启用项。
- 导出全部当前筛选结果，不受当前页限制。

## 10. 数据模型与兼容迁移

### 10.1 统一组织节点

沿用 `cmdb_org_nodes`，但将 `node_type` 从固定枚举改为节点类型目录引用。节点继续包含项目归属、稳定同步标识、修订号和软删除信息。

新增：

- 组织节点类型目录。
- 人员状态目录。
- 人员调动履历。
- 通用资源归属变更事件。

### 10.2 旧三级数据

- 现有 organization、department 节点保持原层级和名称。
- 现有 group 节点不丢弃，迁移为正式组织节点，类型标记为“待确认类型”。
- 管理员首次进入时可以批量把“待确认类型”改为科室、部门、办事处或自定义类型。
- 人员原有 `org_id`、`department_id`、`group_id` 按最深有效节点确定唯一主要归属。
- 无有效 ID 的历史文本归属进入“未归属”，不得只按名称自动合并。
- `group_id`、`group_name` 和历史路径文本列暂时保留兼容，不在新界面写入。

## 11. API 与事务

核心接口：

```text
GET    /api/cmdb/org-tree
POST   /api/cmdb/org-nodes
PUT    /api/cmdb/org-nodes/{id}
POST   /api/cmdb/org-nodes/{id}/move
POST   /api/cmdb/org-nodes/{id}/archive
GET    /api/cmdb/org-node-types
POST   /api/cmdb/org-node-types
PUT    /api/cmdb/org-node-types/{id}
POST   /api/cmdb/org-node-types/{id}/archive
GET    /api/cmdb/person-statuses
POST   /api/cmdb/person-statuses
PUT    /api/cmdb/person-statuses/{id}
POST   /api/cmdb/person-statuses/{id}/archive
POST   /api/cmdb/persons/transfer
```

人员调动请求包含人员 ID、目标节点 ID和资源处理模式；逐项模式包含复合资产引用列表。后端重新读取人员和资源现状，不能信任前端传入的原归属。

错误必须明确指出：无效目标、停用节点、跨项目对象、人员编号冲突、状态不允许分配资源、资源引用失效、节点形成环路或事务回滚原因。

## 12. 测试策略

### 12.1 后端

- 每项目唯一根节点。
- 任意层级树查询、移动防环、停用引用保护。
- 自定义节点类型和人员状态的项目隔离及引用保护。
- 人员编号生成、手填、唯一性和并发冲突。
- 人员只能有一个主要归属。
- 单人、批量拖拽对应的事务调动。
- 三种资源跟随模式及失败整体回滚。
- 已离岗人员不可接收新资产。
- 旧三级组织、分组和文本归属兼容迁移。
- 组织人员导入预览、提交回滚和导出全部筛选结果。

### 12.2 原生界面

- 任意层级组织树正确展开、搜索和显示人数。
- 单人拖拽、勾选多人拖拽及目标高亮。
- 停用节点和未归属节点不能接收人员。
- 资源确认窗口三种模式准确提交。
- 人员表单没有邮箱和工作组，人员编号可自动生成。
- 节点类型和人员状态可配置。
- 深浅主题、窄窗口、长节点名称、空状态和错误状态无遮挡。

## 13. 验收标准

| 编号 | 合格标准 |
| --- | --- |
| AC-01 | 每项目只有一个根机关单位，根节点不能删除、移动或停用。 |
| AC-02 | 组织树支持任意层级，并可表达办事处、派出机构和自定义节点。 |
| AC-03 | 不再出现工作组、所属分组或多部门任职。 |
| AC-04 | 人员只有一个正式归属节点，组织路径由节点关系实时计算。 |
| AC-05 | 节点类型和人员状态均可配置、停用并具备引用保护。 |
| AC-06 | 人员编号项目内唯一、必填并支持自动生成。 |
| AC-07 | 人员表单、列表、详情和导入导出不显示邮箱。 |
| AC-08 | 单个人员和批量选中人员均可拖到正式节点。 |
| AC-09 | 人员调动提供资源全部跟随、全部保留和逐项选择。 |
| AC-10 | 人员和选定资源在同一事务中更新，失败整体回滚。 |
| AC-11 | 人员调动和资源归属变化分别写入可追溯履历。 |
| AC-12 | 已离岗人员不能接收新资产，公共资产允许只有组织归属。 |
| AC-13 | 组织及人员均支持导入预览、事务提交和全量筛选导出。 |
| AC-14 | 旧 group 数据保留为待确认正式节点，不静默删除或按名称猜测。 |
| AC-15 | 正式界面使用 Netcatty 原生组件，保持紧凑密度和原生主题。 |

## 14. 回滚边界

- 新目录表、履历表和主归属列不通过回滚删除。
- 新组织界面可暂时回退旧人员页面，但旧页面只能读取兼容列，不能恢复写入工作组。
- 旧 `group_id/group_name` 保留一个稳定发布周期，再另行评估清理。
- 人员调动事务功能可独立关闭，组织浏览和人员 CRUD 继续可用。
