# Netcatty 原生 CMDB 模块集成设计

## 1. 结论

CMDB 不再以独立浏览器页面或 Netcatty 插件网页视图交付，而是直接编译进 Netcatty 主渲染进程，成为与“主机与密钥”“SFTP”等并列的原生一级工作区。

Go + SQLite 继续作为本机 API 数据服务，由 Electron 主进程随 Netcatty 启动和退出。CMDB 前端通过 Netcatty preload 暴露的专用 IPC 桥访问服务，不显示浏览器、不打开 localhost 地址，也不使用 `view.html`、iframe 或插件 BrowserView 承载业务界面。Netcatty 启动服务时启用 API-only 模式，不提供静态浏览器页面。

本设计替代 `2026-09-15-frontend-rebuild-design.md` 中关于独立浏览器壳、浏览器 URL 状态和一级导航载体的内容。原文确认的业务操作、数据完整性和页面能力继续保留。

## 2. 目标与非目标

### 2.1 目标

1. 在 Netcatty 顶部标签区提供固定的 `CMDB 资产管理` 一级入口。
2. 在 Netcatty 主内容区直接渲染 React 18 + Ant Design 5 CMDB 工作区。
3. 保留全局查询、终端资产、基础设施资源、业务系统、运维履历、IP 规划池和统计概览。
4. 保留终端资产的新增、修改、调换使用人、维修换件、履历、注销归档和按筛选导出能力。
5. 保持 Go API、SQLite 数据和现有资产履历不丢失；错误必须真实可见。
6. 继续通过可重复的装配脚本把本仓库集成层注入锁定的 Netcatty 上游提交。

### 2.2 非目标

- 不把 CMDB 做成独立网站、iframe、远程页面或插件 HTML 页面。
- 不引入 MUI、ORM、FTS、缓存、异步导出、复杂路由或全局状态框架。
- 不新增泛化的“配置中心”或“配置能力”一级入口。
- 不重写 Netcatty 的终端、SSH、SFTP、主机库和 AI 能力。
- 不把基础设施资源误称为物理服务器或服务器资源。
- 不在本轮修改 SQLite 核心数据模型；仅在现有接口无法承载已确认操作时补充最小 API。

## 3. 用户可见信息架构

### 3.1 Netcatty 一级入口

Netcatty 顶部根标签新增：

`CMDB 资产管理`

标签 ID 固定为 `cmdb`，由 Netcatty `activeTabStore` 管理。它是原生根标签，不属于可关闭的临时插件标签。切换到终端、主机库或 SFTP 后，CMDB 工作区保留当前子模块、筛选条件、页码和已打开详情；应用重启后不要求恢复未提交表单。

### 3.2 CMDB 顶部模块导航

采用已确认的 C 方案：顶部模块导航和超宽数据台账，不使用 CMDB 左侧一级侧栏。

导航顺序固定为：

`全局查询 | 终端资产 | 基础设施资源 | 业务系统 | 运维履历 | IP 规划池 | 统计概览`

- 默认进入 `全局查询`。
- 核心业务模块始终直接可见，不藏入“更多”菜单。
- 现有业务流程确实需要的组织、字段或分类维护，只作为对应模块中的辅助管理操作保留，不抽象成独立配置中心，也不占用顶部业务导航。

### 3.3 业务术语

- `终端资产`：云桌面终端、盒子、显示器及其使用人和位置。
- `基础设施资源`：服务器、虚拟机、交换机、路由器、安全设备、存储设备等。
- `业务系统`：业务应用、中间件、数据库服务和基础支撑服务。
- 不再把上述对象统称为“物理服务器和系统应用”。

## 4. 界面与交互规范

### 4.1 外壳

- 使用 Netcatty 原生顶部标签、窗口控制、主题和主内容区。
- CMDB 内不再渲染项目自己的应用顶栏，不显示服务地址或浏览器导航。
- CMDB 使用 Ant Design 5 组件；通过 Netcatty 当前主题变量映射 `ConfigProvider` token，使明暗模式、背景、边框、文字和强调色与宿主一致。
- 页面定位为中高密度运维工作台，不使用营销页、装饰性大卡片、渐变或无意义动效。

### 4.2 全局查询

- 默认首页使用紧凑搜索栏，支持姓名、资产编号、SN、IP、房间和系统名称。
- 查询终端资产、基础设施资源、业务系统、运维履历和 IP 地址。
- 结果按类型标识，但保持统一列表密度；点击结果直接打开对应详情或定位到 IP 地址。
- 右侧关系预览展示当前责任人、部门、房间、网络地址、关联资源和最近履历。
- `Ctrl+K` / `Cmd+K` 在 CMDB 工作区内聚焦全局查询。

### 4.3 台账页面

- 页面首部只保留标题、记录摘要和当前模块的主要操作。
- 查询条件集中在单行工具栏，窄宽度时允许换行，不遮挡操作列。
- 数据表优先占用横向空间，分页固定在表格下方。
- 终端资产默认隐藏已注销记录，但可通过状态筛选查回。
- 资产导出使用当前筛选条件并导出全部匹配记录，不受当前页限制。

### 4.4 详情与编辑

- 详情从右侧抽屉覆盖当前列表，不永久压缩表格为三栏。
- 关闭详情后保留模块、筛选条件、页码和滚动上下文。
- 终端资产详情包含档案、关联对象和运维履历。
- 关联对象必须来自真实接口；无明确关联时显示“未关联”，不得伪造关联。
- 新增和编辑使用 antd 表单弹窗或宽抽屉；调换使用人、维修换件、注销归档保持独立流程。
- 注销归档必须保留原记录并新增履历，不允许物理删除终端资产历史。

### 4.5 状态反馈

- 加载使用与表格或详情结构一致的 Skeleton，不使用整页旋转图标。
- 空数据、无匹配结果、未关联、服务未启动和请求失败使用不同文案。
- 写操作失败时保留用户输入和当前弹窗，不关闭、不伪造成功。
- 成功后刷新受影响的列表、摘要、详情和履历，不刷新整个 Netcatty 窗口。

## 5. 原生集成架构

### 5.1 调用链

```text
Netcatty TopTabs / activeTabStore
            |
            v
原生 CmdbWorkspace（React + antd）
            |
            v
infrastructure/services/cmdbBridgeClient
            |
            v
window.netcatty.cmdb* preload API
            |
            v
electron/bridges/cmdbBridge.cjs
            |
            v
127.0.0.1:18080 Go API
            |
            v
SQLite assets.db
```

渲染器不直接读取 SQLite，也不持有数据库路径。Go 服务继续绑定回环地址，外部网络不可访问。

### 5.2 Netcatty 渲染器接入

装配后的 Netcatty 源码新增独立 CMDB 目录，职责边界如下：

```text
components/cmdb/
├── CmdbWorkspace.tsx
├── CmdbNavigation.tsx
├── search/
├── assets/
├── infrastructure/
├── systems/
├── audit/
├── ip-pool/
└── dashboard/

infrastructure/services/
└── cmdbBridgeClient.ts
```

- `TopTabs` 增加原生 `cmdb` 根标签。
- `AppView` 在 `activeTabId === 'cmdb'` 时挂载 `CmdbWorkspace`。
- CMDB 状态在自身模块内管理，不扩散到 Netcatty 的 vault、terminal 或 workspace domain。
- CMDB 页面不通过 `PluginContributionHost`、`pluginViewTabStore` 或插件 `view.html` 渲染。

### 5.3 前端源码复用

现有 `web/src` 作为字段、接口和成熟业务流程来源。实施时把可复用的业务组件拆成不依赖独立浏览器壳的 CMDB 工作区组件，再由装配脚本复制到 Netcatty 渲染器目录。

- 用户发布物中不提供独立浏览器入口。
- Go 服务始终由 Netcatty 使用 `-api-only` 启动；该模式只注册 `/api/` 路由和健康检查，不注册静态页面，也不会尝试打开浏览器。
- 独立 web 构建只用于复用源码、构建检查和必要的组件隔离调试，不作为用户产品或验收入口。
- 不维护两套功能不同的 CMDB 页面；Netcatty 原生模块是唯一交付界面。

### 5.4 专用 IPC 桥

新增 `cmdbBridge.cjs`，沿用 Netcatty 现有 `registerBridges -> preload/api.cjs -> global.d.ts -> infrastructure service` 模式。

桥接规则：

1. 只接受相对 `/api/` 路径，不接受协议、主机名或文件路径。
2. 只连接主进程管理的固定 CMDB 服务地址，不允许渲染器覆盖 base URL。
3. 支持现有接口需要的 `GET`、`POST`、`PUT`、`DELETE`、JSON 请求和二进制响应。
4. HTTP 非 2xx、超时、服务未启动和响应解析失败均返回可显示的明确错误。
5. 导入文件由 Netcatty 文件选择器取得路径，主进程读取后提交给 Go API；渲染器不直接访问任意本地路径。
6. 导出由主进程取得二进制响应并调用 Netcatty 保存对话框写入用户选择位置，不依赖浏览器下载行为。
7. 每个请求设置有限超时；用户重试产生新请求，不把旧失败伪装成空数据。

### 5.5 Go 服务生命周期

保留并收紧现有 `cmdbService.cjs`：

- Netcatty 启动时解析内置 `cmdb-server` 路径和用户数据目录中的 `assets.db`。
- `main.go` 增加明确的 `-api-only` 启动模式；Netcatty 集成只使用该模式。
- 服务健康检查通过后，CMDB 工作区进入可用状态。
- 服务缺失、端口占用、启动超时或提前退出时，把真实原因传给 CMDB 错误页。
- Netcatty 退出时回收子进程。
- API-only 模式不注册静态页面，也不自动打开浏览器；独立浏览器模式不属于集成版验收范围。

## 6. 构建与装配

本仓库继续只保存自有 CMDB 代码和对锁定 Netcatty 上游的集成层，不提交完整上游副本。

`scripts/prepare-netcatty.mjs` 负责：

1. 校验目标目录和锁定提交。
2. 复制 CMDB 渲染器、IPC 桥、服务生命周期代码和测试。
3. 为 Netcatty `TopTabs`、`AppView`、bridge 注册、preload API、类型声明和打包资源应用唯一锚点补丁。
4. 增加 CMDB 所需的 antd 依赖和构建配置。
5. 停止安装和打包旧 `com.netcatty.cmdb` 网页插件。
6. 任一上游锚点缺失或歧义时直接失败，禁止静默跳过。

发布包继续包含 `cmdb-server` 和数据库初始化数据，但不包含旧 CMDB 插件网页作为界面入口。

## 7. 错误处理

| 场景 | 用户可见结果 | 保留状态 |
| --- | --- | --- |
| 服务启动失败 | CMDB 工作区显示原因、日志位置和重试按钮 | 保留当前标签 |
| 查询失败 | 当前模块显示错误提示，不替换为空列表 | 保留筛选和页码 |
| 详情失败 | 抽屉内显示错误，可重试或关闭 | 保留列表上下文 |
| 新增/编辑失败 | 表单显示真实错误 | 保留全部输入 |
| 调换/维修失败 | 流程不关闭、不刷新假数据 | 保留操作输入 |
| 注销失败 | 不改变本地状态 | 资产仍显示原状态 |
| 导入失败 | 显示解析或提交错误 | 保留预览结果 |
| 导出失败/取消 | 失败显示原因；取消不报错 | 保留筛选条件 |

## 8. 测试与验收

### 8.1 自动化验证

- `go test ./...`
- `web/` 执行 `npm.cmd run build`
- `node --test` 覆盖 CMDB 服务启动、退出、超时和提前退出。
- `node --test` 覆盖 IPC 路径白名单、HTTP 错误、JSON、文件导入和二进制导出。
- Go 测试覆盖 API-only 模式不提供静态页面且 API 健康检查可用。
- 装配到锁定上游后执行 Netcatty lint、现有相关测试和完整构建。
- 检查发布目录包含 `cmdb-server`，且不再依赖旧插件 `view.html`。

### 8.2 原生窗口手测

1. 启动 Netcatty，顶部存在 `CMDB 资产管理` 原生标签。
2. 切换 CMDB 不打开浏览器、不出现 localhost 页面或插件网页边框。
3. 明暗主题切换后，CMDB 与 Netcatty 宿主颜色、边框和文字可读性一致。
4. 全局查询覆盖五类数据并能直接打开对应详情。
5. 五个业务模块查询、筛选和分页正常。
6. 终端资产新增、修改、调换使用人、维修换件、履历、注销归档和导出正常。
7. 基础设施资源可按服务器、虚拟机、交换机、路由器、安全设备和存储设备分类。
8. 业务系统与基础设施资源能够双向查看明确关联。
9. IP 规划池可以查询、分配、释放并进入关联资产。
10. 切换到终端再返回 CMDB，模块、筛选和页码仍在。
11. 模拟服务不可用和接口 500，界面显示真实错误且不丢失表单输入。

## 9. 迁移与回滚边界

### 9.1 迁移

- 删除发布流程中旧 CMDB 插件的构建、自动安装和打包步骤。
- 保留 `cmdb-server` 生命周期管理和 `assets.db` 路径规则。
- 现有数据库无需迁移；原有 Go API 继续兼容。
- 集成版使用 API-only 模式，旧浏览器页面不再作为交付入口或由该进程提供，用户数据不受影响。

### 9.2 回滚

- 原生 UI、IPC 桥和 Netcatty 补丁集中在 `integrations/netcatty/` 与装配脚本，可整体撤回。
- Go 后端和 SQLite 数据库保持独立，可在原生 UI 回滚时继续测试和读取。
- 不以删除数据库、回退数据结构或物理删除记录作为界面回滚手段。

## 10. 验收标准

| 编号 | 合格标准 |
| --- | --- |
| AC-01 | CMDB 是 Netcatty 原生根标签，不通过浏览器、iframe 或插件网页视图展示。 |
| AC-02 | 默认进入全局查询，顶部模块导航与确认稿一致。 |
| AC-03 | 使用“基础设施资源 / 业务系统”术语，基础设施包含服务器和交换机等真实类型。 |
| AC-04 | 查询、分页、详情联动、增改、调换、维修、注销、履历和导出能力完整。 |
| AC-05 | 注销保留资料和履历；导出使用全部匹配记录；关联只展示真实数据。 |
| AC-06 | 服务和接口错误显式展示，失败不清空数据、不关闭输入表单、不伪造成功。 |
| AC-07 | Netcatty 启停负责 Go 子进程生命周期，数据库位于用户数据目录。 |
| AC-08 | Go 测试、前端构建、IPC 测试、Netcatty lint 和完整构建通过。 |
| AC-09 | 原生窗口完成核心流程手测，并保留可定位的截图或日志证据。 |
