## 3. 关键实现

1. **反向写穿**：批量/单条编辑映射来的记录时，除更新 `cmdb_assets` 外，还把可映射字段写回源表——
   - `legacy_asset`：部门→`assets.department`、负责人→`assets.user_name`、备注→`assets.remark`、状态→`assets.status`（在线→在用、在库→闲置、维护中→维修中、报废→已报废）
   - `legacy_server`：负责人→`servers.admin_user`、机柜名称→`servers.location`、备注、状态（在线→运行中、离线→已停机、在库→备用）
   - 纯 CMDB 字段（所属组织/分组/分类/数据中心/楼层/机柜）只写 CMDB
2. **空值不写穿**：在 CMDB 里把字段清空**不会**清空源台账，避免误操作抹掉台账里真实存在的信息；需要清空请到源台账模块操作（界面已明示）。
3. **删除保护**：映射来的记录**拒绝删除**，并说明「删除后下次同步会重新出现，如需停用请改为归档，或到源台账中注销」；纯 CMDB 记录可删。
4. **批量克隆**：复制为新记录（名称加「-副本」，编号/SN/管理IP/MAC 清空，来源标记 `manual`，并复制网络接口）。
5. **批量归档**：状态置「报废」并同步回源台账。
6. **修复映射缺口**：`assets.user_name` 现会映射为 `cmdb_assets.owner`，并对历史数据做幂等回填（本次启动回填 **505** 条）。

## 4. ⚠️ 过程中的数据事故与恢复（如实记录）

**处置**：
1. 立即通过批量编辑把 `owner=邹婷婷` 写回，源台账恢复为 `使用人=邹婷婷 / 部门=民三 / 状态=在用`；
2. 全表排查测试残留（批量测试部 / 测试员 / 临时改名 / -副本）：**0 条**；
3. 修复根因（映射缺口 + 负责人回填）；
4. 追加「空值不写穿」规则与对应测试，从机制上杜绝此类误抹；
5. 追加 `BackfillLegacyAssetOwner` 幂等回填。

**最终数据核对**：`assets 683`、`servers 3`、`cmdb_assets 686`、`ip_pool 1267`，与合并前完全一致。

## 7. 已知限制

1. **旧「统一资源管理」的能力并未 100% 等价迁移**：
   - **已迁移**：批量编辑 / 批量克隆 / 批量归档 / 台账增改 / 删除保护
   - **未迁移（有意）**：「资产拓扑」页签——旧实现为硬编码假页面
   - **未迁移（未做）**：跨类型聚合列表（终端+服务器+应用+IP 混排）。新 CMDB 的「资源管理」已提供终端+服务器的统一 30 列视图，但**不含系统应用与 IP 资源**两类
2. **新 CMDB 无导出**：旧模块的 `导出` 走 `/api/export/assets`（导出源台账），云桌面终端台账模块已有该能力；新 CMDB 的 cmdb_assets 导出未实现。
3. **来源台账的更新时间被写穿牵连**：批量编辑映射记录会同时更新 `assets.updated_at`，合规上属于「CMDB 操作改动了台账」，已在界面明示。
4. **写穿是「尽力而为」**：`servers` 没有「部门」字段，因此在 CMDB 改部门**不会**写回服务器台账（该字段对服务器只存在于 CMDB）。
5. **旧入口下线但代码保留**：`CMDBResources.jsx`（63KB）仍在打包产物中（随 `App.jsx` 的保留分支引入），会占体积；如需彻底移除以减小包体，需要另行确认。

```

全院运维履历总账
IP 规划池
全景统计看板
```

旧模块的**真实能力已迁入新 CMDB**（批量编辑/克隆/归档、新增/编辑/删除、详情抽屉），并借迁移之机补上了反向写穿与删除保护；旧模块的**假拓扑页签按原则不予迁移**；旧源码保留可恢复。

过程中发现并修复了一个**映射缺口**（`user_name → owner` 遗漏），也如实记录了由此引发并已完全恢复的一次数据事故。
