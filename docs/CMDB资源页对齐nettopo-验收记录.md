## 1. 参考页实测结构

从截图与 DOM 清单确认的真实结构：

- **筛选行**：视图下拉（`我的资产`）+ 搜索框（占位符 `搜索资产 (名称, SN, IP...)`）+ 蓝色「搜索」按钮
- **操作行（8 个按钮，顺序与文案固定）**：`分类管理`、`批量编辑`、`批量克隆`、`批量删除`、`下载模板`、`批量导入`、`资产导出`、`新增资产`（最右、蓝色主按钮）
- **表头**：勾选框列 + 30 列；`资产编号`/`设备名称` 带排序箭头，`状态`/`设备分类`/`操作系统类型`/`操作系统版本`/`管理IP`/`业务监控` 带筛选图标
- **业务监控列**：灰点 + `未配置`
- **行内操作**：`编辑`、`删除`、`⋯`
- **分页**：`共 N 条记录  当前 x-y  每页 N 条` + `上一页 / 第 a / b 页 / 下一页 / 跳至 __ 页 / 跳转`
- **顶部导航**：每项带图标

## 4. 与参考站的**有意差异**（据实说明，非疏漏）

| 差异 | 原因 |
| --- | --- |
| 视图下拉默认 `全部资产`，而非 `我的资产` | 参考站的「我的资产」依赖登录用户体系；本项目是本地单用户台账，没有用户表（`AGENTS.md` 亦禁止新增人员表）。改为按**数据来源**划分的真实视图：全部 / 云桌面终端 / 物理服务器 / 手工登记 |
| `管理IP`、`业务监控` 两列**没有**筛选图标 | `管理IP` 已被顶部关键字搜索覆盖（搜索即匹配 mgmt_ip 等字段）；`业务监控` 本项目无采集端、全部恒为「未配置」，加筛选器是无意义的。**不做假交互** |
| `批量删除` 实际执行「注销归档」 | `AGENTS.md` 明确要求「删除采用注销归档：保留资产资料和履历」。按钮文案对齐参考站，但确认框会明确说明「不会物理删除」 |
| `下载模板` 与 `批量导入` 被做成了**严格匹配的一对** | 原项目的模板接口产出的是资产台账模板，而导入接口只认深信服报表格式，两者**本来不匹配**。本轮统一为同一套表头（18 列），并写了「模板能被自己的导入解析」的往返测试 |
| 行内 `⋯` 的内容 | 参考站的 `⋯` 展开内容未被采集，本轮放入本项目真实可用的动作：详情 / 克隆为副本 / 归档 |

## 7. 已知限制

1. **`业务监控` 恒为「未配置」**：本项目无采集端、无被管设备可联调（原计划 P2 阶段），该列只是如实反映现状，不是真实监控数据。
2. **`位置标识`（`cabinet_position`）仍恒为 `-`**：阶段 A 未落地该字段，导出时该列也输出空值。
3. **列头筛选目前支持 4 列**（状态 / 设备分类 / 操作系统类型 / 操作系统版本）：其余列后端未提供对应筛选参数；如需扩展，按同一模式加后端参数即可。
4. **「我的资产」视图未实现**：没有用户体系，无法按登录人过滤。
5. **导入按名称匹配分类**：模板里的「设备分类/所属组织/所属分组」若不存在，该字段留空并在校验结果中提示，**不会自动创建分类**（避免导入污染分类树）。

## 8. 结论

CMDB 资源页已按参考站 `https://nettopo.com/cmdb/resources` 重构：

**两行工具栏（视图 + 搜索 / 8 个操作按钮，文案与顺序逐字一致）→ 列头筛选 → 30 列表格（业务监控显示「未配置」）→ 行内 编辑 / 删除 / ⋯ → 分页与跳转**

并顺带补齐了参考站有而原本缺失的四个能力：**资产导出**（按筛选导全量）、**下载模板**、**批量导入**（校验 + 提交）、**批量删除**（按项目规则执行注销归档）。其中模板与导入做成了严格匹配的一对，并写了往返测试锁死。

**后端 40 个测试全绿、前端构建成功、7 项端到端核对通过、数据与改动前完全一致。** exe 已重新打包（20:53 版本）并启动；第 6 节的 5 项需你在浏览器中确认。
