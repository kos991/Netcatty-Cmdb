# IP 规划池 · 重新规划验收记录

- 验收日期：2026-09-14
- 触发原因：用户反馈「IP 规划池你这个我怎么做交互？重新规划下 太乱了根本看不懂」
- 本轮目标：重做 IP 规划池的**信息结构与交互**——从「一进来就掉进 253 行只读明细」改为「网段总览 + IP 方格矩阵 + 可分配/释放/编辑」。

## 2. 数据修复：外网段 255 条复合地址

**发现**：外网段全部 255 条记录的 `ip` 字段是复合字符串，例如
`191.162.17.1 (盒子:180.161.30.1)`，而专网 7/8/9/10 段 253×4 条全部是纯 IP。

**根因**：v2 迁移时为了不丢失「盒子地址」才拼接在一起——该盒子地址正是资产表 `terminal_ip` 的值（315 台资产有 `terminal_ip`，多为 `180.161.30.x`），是 IP 与资产联动的唯一钥匙。

**处置**（`ip_pool` 表结构不可变更，故不动表结构）：

| 项 | 处理 |
| --- | --- |
| `ip` 字段 | 规范化为纯地址 `191.162.17.1` |
| 盒子地址 | 保留到 `remark`：`外网云桌面｜盒子 180.161.30.1`，由 `BoxIPFromRemark()` 解析读取 |
| 执行方式 | `main.go` 启动时调用 `NormalizeIPPoolIPs()`，**幂等**、只处理匹配已知复合格式的行、事务提交 |

实测：启动后 255 条全部规范化，`ip` 为纯地址、备注保留盒子地址，重复启动不再改动。

## 4. 关键实现

1. **网段总览**：5 张网段卡片 + 合计卡，显示地址范围、进度条使用率、总/占/空。点卡片切换网段。
2. **IP 方格矩阵**（默认视图）：按 IP 末位排版，每格一个地址；空闲=绿、已占用=红、无记录=灰虚线；悬停显示 IP/状态/使用人/部门/房间/占用资产/备注；点击打开详情抽屉。搜索与筛选**不匹配的方格淡出但保留位置感**。
3. **列表视图**：可切换，含 IP/状态/使用人/部门/房间/占用资产/备注/操作。
4. **真正的交互**：
   - 分配：仅空闲可分配，必须填使用人或部门；已占用再次分配会被拒绝
   - 释放：二次确认，置回空闲并清空占用信息；空闲状态重复释放会被拒绝
   - 编辑 / 补录 / 删除：补录校验 IP 格式与重复
5. **统计口径修正**：网段容量与使用率来自后端**全量聚合**（`IPPoolSummaryData`），彻底修掉「只统计当前页」的 bug。
6. **搜索修正**：关键词参与筛选并重置页码，矩阵与列表共用同一套条件。
7. **数值排序**：SQLite 侧用 `CAST(REPLACE(ip, rtrim(ip,'0123456789'),'') AS INTEGER)` 按末位排序，修掉 `.10` 排在 `.9` 前的问题。
8. **网段自然排序**：按前缀数值排序（7→8→9→10→外网），修掉字符串序把「10段」排到「7段」前。
9. **资产联动**：专网按 `assets.ip` 匹配；外网按备注中的盒子地址匹配 `assets.terminal_ip`。
10. **导出**：按当前筛选导出**全部匹配记录**（非当前页），CSV 带 UTF-8 BOM，另支持 xlsx。

## 7. 已知限制

1. **矩阵需要整段数据**：为渲染方格图，前端一次拉取该网段全部条目（`page_size=500`，实际 253~255 条），因此**未使用服务端分页**。单网段地址量级（≤500）下无问题，若未来出现 /16 级大网段需要改为按需加载。
2. **外网盒子地址存在备注里**：受「不得修改 `ip_pool` 表结构」约束，盒子地址只能寄存在 `remark` 字段（格式 `外网云桌面｜盒子 180.161.30.N`）。若用户手工改动该备注格式，外网段的资产联动会失效。
3. **补录只能在有空缺的网段生效**：7/8/9/10 段均为 2~254 连续满编，常规补录会被「IP 已存在」拒绝；补录主要用于新增网段或填补空缺地址（如 `.1` 网关预留）。
4. **资产联动是单向只读**：从 IP 能看到占用资产，但从资产侧看不到「我占用了哪个 IP」的 IP 池条目（资产模块已有 `relations` 接口，本轮未改）。
5. **测试脚本自身踩坑一次**：PowerShell 中「字段缺失」是 `$null` 而非 `""`，导致我第一轮误判资产联动未生效；改用 `PSObject.Properties` 判断后确认联动正常。**非应用缺陷。**
